# W27 slice E independent review — 2026-10-03

**Verdict: CHANGES-REQUIRED** for `groundhog/w27-ui-followups` at `ffb87f06` against `3b6bcc57` (commits `a6631458` through `ffb87f06`). Review branch: `review/w27-ui-followups`.

## Findings

1. **Blocker — F3's first persisted miss aborts the leave path.** `gnome/groundhog/src/mls/gh-mls-service.c:4322-4323` writes the cursor in SQLite autocommit mode, then calls `gh_store_commit()` without `gh_store_begin()`. The store API asserts `depth > 0` (`src/store/gh-store.c:1028-1032`). The opt-in `/groundhog/mdk-interop/groundhog-leaves-mdk-admin` case reproduced `FATAL-CRITICAL: gh_store_commit: assertion 'store->depth > 0' failed` after the first ignored Remove request. With the project's fatal-critical test setting this kills Groundhog rather than retrying or reaching the bounded failure. Use an explicit transaction (and check write/commit errors) or rely on the cursor statement's autocommit; add a restart/persistence test.

2. **High — the promised second press still asks admins again.** `gnome/groundhog/src/mls/gh-mls-service.c:6464-6484,6514-6517` makes `leave_kind()` report `GH_MLS_LEAVE_DEVICE` after `NOT_PROCESSED`, so the confirmation says this device will leave. But `gh_mls_service_leave()` clears `leave_failure` before its `marmot_can_self_remove()` branch and calls `marmot_self_remove()` again, making a new admin request. The added assertion in `tests/mls/test_mdk_interop.c:1202` checks only the label, not the effect. Preserve the failure state until selecting the actual device-only operation and test the second confirmed leave.

3. **High — copied Adwaita icons have no recorded licence/provenance.** `gnome/groundhog/data/groundhog.gresource.xml:9-50` bundles 36 copied Adwaita 51.0 SVGs (per `c0933307`), but no icon attribution or separate asset licence was added under Groundhog; `data/org.nostr.Groundhog.metainfo.xml:6` and the About dialog still present MIT alone. [Upstream COPYING](https://github.com/GNOME/adwaita-icon-theme/blob/master/COPYING) offers LGPL v3 or CC-BY-SA 3.0 US and asks for GNOME Project attribution/link. This does not necessarily preclude MIT *code*, but distributed artwork needs its own chosen licence/notice and provenance, rather than appearing MIT-licensed. Record these with the assets and make the About/distribution notices unambiguous.

4. **High — the icon test does not cover every referenced icon.** `gnome/groundhog/tests/ui/test_icons.c:15-59` uses a manually curated array, not a reference audit or a `GtkIconTheme` lookup. For example, `data/ui/gh-mls-relay-row.blp:17` references `network-server-symbolic` and `data/ui/gh-onboarding-view.blp:91` references `dialog-password-symbolic`; neither is bundled. `changes-prevent`, `face-smile`, `list-add`, `list-remove`, `system-search`, and others are absent too. On a desktop without a theme supplying one of these, the stated non-GNOME guarantee fails while the test remains green. Derive/test the names in Blueprint and C, or explicitly test/document each proven GTK builtin and hicolor fallback.

5. **Medium — local vote withdrawal leaves the tally in memory.** `gnome/groundhog/src/mls/gh-mls-service.c:8308-8311` computes `inner_id` but applies the local vote with `vote_event_id = NULL`. The withdrawal handler at `:2868-2888` first tries to remove a poll keyed by the withdrawn *vote* ID, then searches voter records by that ID; neither finds the local vote. A convergence reorg withdrawing the account's own vote leaves the tally and local selection until restart. Pass `inner_id` and add a service-level withdrawal test, not only the direct `GhMlsPoll` helper test.

6. **Medium — same-choice re-votes keep an obsolete vote ID.** `gnome/groundhog/src/mls/gh-mls-poll.c:467-477` returns before updating `vote_event_id` when the option IDs match. If Bob votes A twice and convergence withdraws the second event, lookup misses; if it withdraws the first, it removes Bob despite the surviving second vote. Track the newest event ID even when tallies do not change, and test both withdrawals.

7. **Medium — F1 does not mean an *empty* admin Commit.** `gnome/groundhog/src/mls/gh-mls-service.c:2712-2721` regards any admin Commit with `departed_count == 0` as a miss, including one adding a member, changing group state, or processing non-departure work. Two such Commits can exhaust the leave budget even though the admin is active and may process the Remove next. Match the specified empty-Commit condition, not merely “no departure,” or narrow the claim and test a nonempty admin Commit.

8. **Medium — reply controls can be visible but inert.** `gnome/groundhog/src/ui/gh-message-row.c:400-425` shows an actionable button for any parsed target ID; `gh-conversation-view.c:1724-1741` silently returns if the target is absent from this conversation or the loaded timeline. An older unloaded message, a blocked/request-only message, or a cross-group quoted event produces a focusable “Replying to …” button that cannot jump. The code does not fetch or expose inaccessible content, which is good, but it needs an unavailable/non-actionable state or an explicit safe load-in-this-conversation flow and a GUI test. The accessible label is present. Separately, `gh-message.c:565-568` treats a marked `e` mention as the bare-e reply fallback; an event with only `['e', id, '', 'mention']` gets a false reply header. Restrict the positional fallback to genuinely unmarked `e` tags.

9. **Medium — the broadened privacy test failed the required Linux sanitizer gate.** `gnome/groundhog/tests/privacy/test_privacy_mls.c:421` observed `member_naming_reqs(&w.e, CAROL) + member_naming_reqs(&w.w, CAROL) == asked` as `3 == 2` in the gate's parallel run. The macOS run passed. There was no sanitizer report; this is either a newly exposed member-naming REQ or an asynchronous test baseline/race. Determine which, fix it, and rerun the gate. The broadened helper at `:304-315` does count REQs regardless of kind, as requested.

10. **Nit — version assessment has no slice-E manifest row.** Groundhog is still unreleased at `0.12.0`; a further version bump is not needed for these Groundhog changes, and the `libmarmot/src/commits.c` edit is comment-only (no libmarmot bump). But the brief requested a `VERSION_MANIFEST.md` row and the component policy requires recording the no-further-bump decision.
