### Resolution of the prior findings

1. **Room confinement — fixed.** `gh-store-reactions.c:64-87` admits a reaction only when a `messages.backend_msg_id` for its target exists in the `conversations.backend_key` claimed by the reaction. The sink constructs that key from the verified reaction author plus its `p` tags (`gh-app-outbox.c:262-281`); [NIP-17 defines the room by exactly that set](https://github.com/nostr-protocol/nips/blob/master/17.md#chat-rooms). Thus C's C–A reaction cannot attach to A–B's target, even though the in-memory summary is target-ID keyed. Restore performs the same target/room join (`gh-store-reactions.c:208-215`). The new three-account negative assertion checks no chip and no reaction row on A, both live and after restart (`test_e2e_dm.c:604-622,660-662`). Rebuilding only the old store delegate made that test fail at line 618: C's `x` chip appeared. A reviewer-only three-party wire probe sent an A→B,C message and B→A,C reaction and verified the reaction persisted in the A–B–C room on both A and C; it passed. No permanent positive three-party assertion was added by the author, but the predicate itself does not restrict room cardinality.
2. **CI registration — fixed.** `.github/workflows/groundhog-ci.yml:73,119,238` now lists both `test-groundhog-reactions` and `test-groundhog-reaction-send` in the build list, their CTest names in the required set, and both in the sanitizer test set. The sanitizer gate parsed the candidate workflow and ran all 60 listed tests without a skip.
3. **Same-second toggle — fixed for ordered delivery.** `gh-nip17-envelope.c:573-585` adds a fresh UUID-valued `nonce` tag only in the kind-7 NIP-17 rumor constructor. NIP-01's ID hashes tags, so same-second off/on no longer reuses the old ID; the kind-5 deletion still refers only to the old ID. The committed fixed-clock test (`test_outbox.c:2453-2490`) fails against the pre-fix constructor at line 2472 with the expected `messages.conversation_id, messages.backend_msg_id` UNIQUE constraint, then passes with the fix restored. ### Interoperability and remaining limits

- **Nit — cross-client evidence is structural, not a NIP-17 interop run.** The `nonce` is an ordinary extra rumor tag; it does not alter the NIP-59 seal or gift wrap, nor the required NIP-25 `e`/optional `k` references ([NIP-01 tags](https://github.com/nostr-protocol/nips/blob/master/01.md#tags), [NIP-25](https://github.com/nostr-protocol/nips/blob/master/25.md#tags)). [Amethyst's `ReactionEvent`](https://github.com/vitorpamplona/amethyst/blob/main/quartz/src/commonMain/kotlin/com/vitorpamplona/quartz/nip25Reactions/ReactionEvent.kt) keeps the tag array and extracts `e`/`p`/`a` by tag type; its [NIP-17 factory](https://github.com/vitorpamplona/amethyst/blob/main/quartz/src/commonMain/kotlin/com/vitorpamplona/quartz/nip17Dm/NIP17Factory.kt) wraps reaction events without a fixed tag whitelist. That supports ignoring the extra tag when interpreting a reaction, but I did not run Amethyst. The passing MDK/White Noise `white-noise-reactions` case uses **MLS** application messages, not NIP-17 kind-7 rumors, so it cannot prove that client accepts this nonce; MDK/White Noise's MLS path is unaffected by it. Do not describe that test as NIP-17 nonce interop coverage.
- **Low, non-blocking follow-up — out-of-order kind-5 before the old kind-7 does not converge.** `gh-app-outbox.c:320-326` only removes a reaction already present in the in-memory store; there is no deletion tombstone. If multi-relay delivery brings the deletion before the original reaction, the deletion is ignored, and old then new kind-7 rumors produce two chips despite distinct IDs. This is an older NIP-09 delivery-order gap, not the same-second ID collision fixed here; track it separately rather than claiming unconditional latest-state convergence. [NIP-09](https://github.com/nostr-protocol/nips/blob/master/09.md#client-usage) expects clients to honor valid deletion requests. The ordered live receiver path does converge, as verified above.
- **Low, accepted deferral — reaction before its target.** `delegate_admit` returns false if the target message is absent, including in a known room (`gh-store-reactions.c:86-87`); the sink does not persist a pending reaction (`gh-app-outbox.c:307-309`). `nostrc-r41l` explicitly tracks durable pending/reconciliation with reaction-first, restart, and wrong-room coverage. Deferring it is acceptable for this security-focused slice because the current behavior fails closed: a premature reaction is absent, never projected onto an unrelated bubble. It remains a user-visible eventual-delivery gap, not a completed feature.
