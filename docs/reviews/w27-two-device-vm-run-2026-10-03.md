# W27 Groundhog ↔ Groundhog two-device VM acceptance — 2026-10-03

**Release gate:** `nostrc-7gx7` (two-device slice `nostrc-ngvb`). **Result:** the encrypted-group lifecycle passed on two separate Linux installs over real, private relays. NIP-17 DM passed in both directions after retrying one signer-expired send. The additional reaction and media checks did **not** pass end-to-end. This is not evidence for the separate White Noise/MDK third-party criterion (see `nostrc-3cbn`). Do not flip the encrypted-groups shipping flag on the strength of this report alone.

It contains 347 screenshots, VM logs, relay logs, configure/build/CTest logs and VM metadata. Throwaway private keys are **not** copied there. VM run directory: `~/gh-run/20261003T171803/` on each host. Timestamps in VM/relay logs are UTC; screenshots show local UI times.

## Relay and media topology

Both relays were **private local** `nostr-rs-relay:0.10.0` containers on A, bound to `127.0.0.1` only (image digest `061516573b143b44e331f960036a6a3dc43c9b256ef8ca71afedbeb2cf797a4b`). Inbox/discovery/KeyPackage relay: `ws://127.0.0.1:4848` on each VM. MLS group relay: `ws://127.0.0.1:4849`. B reached the same loopback relay URLs through private SSH forwarding supplied by the lab; host addresses and forwarding-hop details are intentionally omitted. No public Nostr relay was used. Two relay roles are required: Groundhog intentionally excludes group relays from public KeyPackage lookup, so trying only one relay produced `No usable relay to look KeyPackages up on` before 4849 was separated. The first-party `nostrc-relayd` was attempted first and rejected Groundhog's `wss` WebSocket subprotocol; see `nostrc-hja5` and `amd64/relay.log`.

For media only, an encrypted test PNG was attempted against a local TLS Blossom fixture and three external HTTPS Blossom endpoints. The normal Groundhog client refuses private-host attachment servers (SSRF protection), so the local fixture was not used to claim a pass. **No public relay** was involved. The external endpoints saw only an encrypted test blob attempt, not plaintext; all rejected the upload, as below.

## Defects and qualifications

- `nostrc-hja5` (P2): first-party relay refuses Groundhog's `wss` WebSocket subprotocol. `amd64/relay.log`: `No supported protocol "wss"` at 00:39:03 UTC; fallback relay was necessary.
- `nostrc-1u9k` (P2): selecting an attachment server in a live session can loop back to server selection without a PUT; restart with the persisted setting made the upload request. `amd64/a-media-server-https.png` and `amd64/a-media-fresh-send.png` distinguish the two states.
- `nostrc-bz4g` (P1): encrypted attachment upload unsuccessful against the three endpoints tested. Server policies, rather than a demonstrated crypto failure, may explain the HTTP responses; a supported end-to-end configuration remains unproven.
- `nostrc-7ash` (P2): both reaction directions had local UI/relay publication evidence but no peer reaction chip. This may be receive/decrypt/projection; do not count either as passed.
- Helper review remediation: `scripts/vm/w27-paths.sh` confines writes to the VM account's fixed `~/gh-run/<timestamp>` tree and rejects path overrides, symlinked run paths, foreign-owned/hard-linked output files, and unsafe build paths. `restart-groundhog` requires a matching executable, UID, PID start time, and launch marker; it waits up to 10 seconds after TERM and refuses overlapping relaunches. On A, isolated safety checks rejected `..`/override input, refused a forged live PID without signaling it, timed out on a TERM-resistant process without spawning another, and restarted a verified process only after exit (`helper-safety-check.log`). `shellcheck -x scripts/vm/*.sh`, Bash syntax, Python AST, and `scripts/check-unsequenced-args.py` passed. `scripts/check_privacy.py` and `scripts/check_data.py` do not exist in this checkout.
- Host quality gates: fresh macOS build succeeded; full macOS CTest recorded 453 pass, 5 skip and 1 intermittent failure out of 459 (`gnostr-test-real-bind-latency`, `Gdk-WARNING: gdk_frame_timings_presented() called on skipped frame`, SIGTRAP), then that test passed 1/1 in isolation (`nostrc-i0c0`). `python3 scripts/check-unsequenced-args.py` passed. The arm64 `scripts/linux-gate.sh` built all targets and passed its 454-test smoke set after isolated retries of three parallel failures: `marmot_test_adopted_commits` timing (`nostrc-12m0`, already tracked), `test_nostr_gtk_bind_latency_budget` 209 ms heartbeat gap over a 200 ms limit (`nostrc-rnql`), and `groundhog-e2e-dm` `inbox_live` exceeding 10 seconds (`nostrc-d9r6`). See `mac-full-ctest.log`, `mac-bind-latency-rerun.log`, `mac-static-check.log`, and `mac-linux-gate.log`. These are gate flakes, not a clean first-pass result.
- Review-fix revalidation: full macOS CTest again recorded 453 pass, 5 skip, 1 parallel-only failure out of 459; this time `gnostr-test-event-item-txn-budget` took 1550 µs against its 1000 µs budget, then passed alone (`nostrc-lx6b`; `mac-full-ctest-reviewfix.log`, `mac-event-item-rerun-reviewfix.log`). The arm64 Linux gate rebuilt successfully and passed all 454 smoke tests after one isolated retry of the already-tracked bind-latency flake (`nostrc-rnql`; `mac-linux-gate-reviewfix.log`). The local HTTPS fixture also started from its fixed run path and stopped cleanly under a bounded timeout (`fixture-path-smoke-reviewfix.log`). No production source changed in this remediation.
- Several manual signer approvals expired after 300 seconds while switching between VMs. This is a test-operation limitation, not itself evidence of an app defect. The failed B DM was retried successfully with prompt approvals. `signer.log` and `daemon.log` show request IDs and expiry. A/B app sessions may show a stale “waiting for signer” banner for old giftwraps; the group lifecycle verdict rests on the independent visible plaintext and persisted-history screenshots.
- `GH_FEATURE_ENCRYPTED_GROUPS` remains gated. This run proves only Groundhog↔Groundhog across two installations, not White Noise interoperability. See the earlier `nostrc-3cbn` device run and release-gate owner decision.

## Reproduce / attach

1. On each VM, clone the pinned SHA recursively and configure/build with the flags above. The run helpers are `scripts/vm/w27-session.sh` (per-user Xvfb/bus/keyring/signer/Groundhog setup) and `scripts/vm/w27-screenshot.sh` (timestamped root screenshots). Set a fresh `W27_RUN_ID=YYYYMMDDTHHMMSS`; helper files are confined to the VM user’s fixed `~/gh-run` root and per-run `~/gh-run/$W27_RUN_ID`, and `W27_RUN_DIR` overrides are rejected. `scripts/vm/w27-blossom-fixture.py --run-id "$W27_RUN_ID"` is the local HTTPS negative-path fixture used to confirm the production private-host guard; put `blossom.crt` and `blossom.key` in that run directory first. It does **not** make media acceptance pass.
2. Use separate inbox/discovery and group relays, both private and reachable as the same loopback URL on each VM. Use only throwaway keys. The signer GUI must be unlocked, and each request approved before its 300-second pending timeout. UI clicks are manual/xdotool; no MLS D-Bus test hook was used.
3. At handoff the Groundhog instances are left open on `DISPLAY=:99` (A PID 80069; B PID 60691). Supply `W27_A_SSH_HOST` and `W27_B_SSH_HOST` from the lab environment (no host/address defaults); attach with `ssh "$W27_A_SSH_HOST"` or `ssh "$W27_B_SSH_HOST"`, then run `DISPLAY=:99 import -window root /tmp/groundhog.png` and copy/view the PNG, or use VNC/xpra bound privately to that display. `amd64/final-groundhog.png` and `arm64/final-groundhog.png` show the final live desktops. The original-run PID is also in `~/gh-run/20261003T171803/groundhog.pid`; logs are in the same directory. The hardened helper deliberately rejects that legacy one-field PID file for restart until it is manually inspected and a new script-managed start records PID, start time, and launch marker; it will not signal the existing process from the legacy record. The temporary relay containers, Blossom fixture, and SSH port-forward jobs were stopped after evidence capture; to resume online interactions, recreate the relay/tunnel topology above. Per-user display/session/secret-service/signer support daemons remain because the GTK instances require them; no VM build or test jobs remain.

**Version impact:** this branch changes only this report and VM-only helper scripts, not a shipped nostrc component: **no version bump**. Groundhog 0.12.0 remains unreleased; no manifest release column changes.
