# NIP-05 as a GDM login identifier — evidence pack (2026-09-22)

Beads: `nostrc-bit0` (this feature) · `nostrc-037i` (follow-up: JIT
enrolment policy) · references `nostrc-zcll.6` (B5).

## Goal

At the GDM greeter's "Not listed?" prompt a maintainer types their
NIP-05 (e.g. `chebizarro@coinos.io`) instead of the local Linux
username.  The broker resolves the identifier to a pubkey, maps it
to the enrolled account, canonicalises `PAM_USER` to the account's
local username, and continues the QR (nostrconnect) login for that
account.  Auth semantics unchanged: the signed challenge is bound
to the account pubkey; spoofing the NIP-05 cannot grant access.
Guarded risks are SSRF / DoS from the greeter and correctness.

## What shipped (all in `gnome/nostr-homed/`)

- **Unprivileged resolver helper** `nostr-homed-nip05`
  (`src/nip05/nostr-homed-nip05.c`).  Forks + drops to `nobody`;
  refuses root (exit 70); syntactically validates `<local>@<domain>`
  per NIP-05; assembles `https://<domain>/.well-known/nostr.json?
  name=<local>` (pct-encoded local); fetches with libcurl,
  `https`-only, 10 s / <= 64 KiB / <= 3 redirects, and — the whole
  point — an `OPENSOCKETFUNCTION` that runs
  `nh_profile_ssrf_check_sockaddr` on every resolved peer.  Emits
  `{"pubkey":"…","relays":[…]}` on stdout; classified exit codes on
  failure (see `include/nostr_nip05.h`).
- **Parent-side client + cache**
  (`src/nip05/nip05_client.c`, `src/nip05/nip05_cache.c`) — fork /
  exec, stdout capture (8 KiB cap), and an in-memory
  `(address → pubkey)` cache (positive TTL default 10 min, negative
  TTL 60 s) with round-robin eviction.
- **Broker integration** (`src/auth/auth_broker.[ch]`) — in
  `do_begin_login`, an `@`-containing username is validated as a
  NIP-05, run through the throttle + cache + resolver, and looked
  up by pubkey via `nh_identity_store_lookup_by_pubkey`.  On
  success the transaction is opened for the canonical account and
  the `BEGIN_LOGIN` reply additively carries
  `account_username` + `identifier`.  On any failure it maps to
  `UNKNOWN_ACCOUNT` (no JIT enrolment in v1).  Broker syslogs the
  mapping — never the fetched body.
- **PAM module** (`src/pam/pam_nostr_broker.c`) — parses the new
  reply fields via `nh_auth_client_begin_login_ex` and, when the
  canonical username differs from what the client typed, calls
  `pam_set_item(PAM_USER, canonical)` and re-fetches `PAM_USER` so
  all subsequent handling names the local account.  Logs one line:
  `nostr: identifier <nip05> -> <user>`.
- **Greeter artifact contract addition** (`src/auth/auth_conf.c`
  + `src/auth/auth_broker.h`) — `nh_broker_greeter_artifact_write`
  gained an optional `account` block emitted as
  `{"username":"…","display_name":"…","identifier":"…","avatar":"avatar.png"}`
  in `/run/nostr-auth/greeter/current.json`; a sibling `avatar.png`
  is copied from `/var/lib/AccountsService/icons/<user>` when
  available.  All three files (`current.json`, `current.png`,
  `avatar.png`) are removed together on retire so the previous
  account's face never lingers.
- **Config keys** in `nh_auth_conf` — `nip05_resolve`
  (on/off, default on), `nip05_cache_ttl` (positive TTL seconds),
  `nip05_image_user` (drop-user override).  Wired into `nostr-authd`.
- **Docs** — `greeter-extension/README.md` (consumer contract for
  the `account` object) and `docs/INSTALLED_LOGIN.md` §5c (operator
  view: alias policy, resolver isolation, wire additions, syslog
  trail).
- **Unit tests** (`tests/unit/test_nip05.c`) — 4 groups:
  syntactic parser (happy / root `_` / rejects), URL assembly (pct
  encoding + overflow), `.well-known/nostr.json` parser (happy +
  wrong name + non-hex + malformed JSON + case-insensitive keys +
  relay hints), cache TTL (positive expiry, negative expiry,
  eviction).

Tests wired into `NOSTR_HOMED_ENABLE_AUTH_RUNTIME` and labelled
`nostr-homed;portable;auth-runtime;nip05`.  The helper's live HTTPS
behaviour is covered by the end-to-end run below.

### 3. Live helper — `nostr-homed-nip05` against `coinos.io`

```
$ sudo -u nobody /usr/libexec/nostr-homed/nostr-homed-nip05 chebizarro@coinos.io
{"pubkey":"cdee943cbb19c51ab847a66d5d774373aa9f63d287246bb59b0827fa5e637400","relays":[]}
exit=0
```

Matches the seeded pubkey for `n_bizarro`.  Negative cases:

| Input | Exit | Meaning |
|---|:---:|---|
| `bob@localhost.localdomain` (resolves to 127.0.0.1) | 65 | SSRF gate refused the peer |
| `zzzzzzzzznobody@coinos.io` | 69 | `.well-known` has no such name |
| `not an addr` | 64 | Syntactic validation refused |
| running the helper as root (`sudo /usr/libexec/…/nostr-homed-nip05 …`) | 70 | Refused |

### 4. Live broker — canonicalisation trail

```
$ sudo pamtester gdm-password chebizarro@coinos.io authenticate
Password: pamtester: Authentication failure
```

(Fails as expected — the maintainer's key is not on this host; the
positive phone run is the maintainer's.)

Broker syslog for the same attempt:

```
nostr-authd[…]: nostr: nip05 chebizarro@coinos.io -> n_bizarro
nostr-authd[…]: nostr: nip05 chebizarro@coinos.io -> n_bizarro (cached)
```

PAM syslog:

```
gdm-password[…]: pam_nostr(gdm-password:auth): nostr: authenticate n_bizarro (nip46qr) -> invalid_proof
```

`pam_nostr` logs the canonical username `n_bizarro` even though
the caller typed `chebizarro@coinos.io` — proof that the
`pam_set_item(PAM_USER, ...)` canonicalisation is live.

### 5. Unknown NIP-05 — `UNKNOWN_ACCOUNT` / `PAM_USER_UNKNOWN`

```
$ sudo pamtester gdm-password ffffthisdoesnotexist@coinos.io authenticate
Password: pamtester: Authentication failure

nostr-authd[…]: nostr: nip05 resolve ffffthisdoesnotexist@coinos.io -> failed rc=69
```

`rc=69` = `NH_NIP05_ERR_NAME` (name not in `.well-known`).  The broker
mapped that to `UNKNOWN_ACCOUNT`; the PAM module mapped
`UNKNOWN_ACCOUNT` to `PAM_USER_UNKNOWN`.  No local account was
touched — v1 alias-only policy.

### 6. Non-NIP-05 path unchanged

```
$ sudo pamtester gdm-password n_bizarro authenticate
```

Broker syslog shows **no** `nip05` line for this attempt.  The
`@`-detection branch is skipped and the transaction opens with
`n_bizarro` directly, matching the pre-NIP-05 behaviour.

### 7. Greeter artifact write path

`inotifywait` on `/run/nostr-auth/greeter/` during a NIP-05 login:

```
CREATE avatar.png.tmp
OPEN avatar.png.tmp
MODIFY avatar.png.tmp
CLOSE_WRITE,CLOSE avatar.png.tmp
MOVED_FROM avatar.png.tmp
MOVED_TO avatar.png
CREATE current.json.tmp
...
MOVED_TO current.json
CREATE current.png.tmp
...
MOVED_TO current.png
```

All three files land atomically (write-tmp + rename).  The extension
observes `current.json` first (per the consumer contract) and finds
`avatar.png` already present.  Structure of `current.json` is
covered by `homed_broker_login_nip46_qr` via the
`nh_broker_greeter_artifact_set_dir` test seam, extended in this
patch with the additive `account` block — the pre-existing test
still passes because the block is emitted only when the caller
provides an account.

## Non-goals / follow-ups

- **JIT enrolment** (bead `nostrc-037i`): auto-provision a local
  account when a NIP-05 resolves to an unenrolled pubkey.  Must be
  off by default and gated by an allowlist — a stranger's NIP-05 at
  the greeter MUST NOT create a local account.
- **Persistent negative cache**: today the 60 s negative cache is
  in-memory only, so a broker restart lets an attacker restart the
  fetch clock.  The design deliberately keeps it small; the per-
  address rate limit is the durable defence.
- **Live phone acceptance** of the positive path is the maintainer's
  work — this evidence pack covers the negative and the
  canonicalisation trail.
