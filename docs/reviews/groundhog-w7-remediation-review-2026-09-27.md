The baseline Actions short-fuzz failure was masked at the job level, and the step still has `continue-on-error: true` (`.github/workflows/nostrc-ci.yml:119-121`), so fuzz findings are **not** a CI gate; do not treat a green workflow as proof of clean fuzzing.

## Addendum — pre-push worktree gate `36c015bd` (`nostrc-8gkz.1`)

### Context / scope

Second independent bounded review of exact **`0e2e90ec..36c015bd886cdb5bc54a4c5c584bffa674624b81`** (one local, unmerged/unpushed commit) from the same report branch. Only `scripts/pre-push` and `scripts/test-pre-push.sh` changed. This addendum does not alter the W7 remediation verdict above.

### Findings

1. **Blocking — stdin can be consumed before the build gate.** The unchanged installer appends `scripts/pre-push` *after* Beads in one hook process (`scripts/install-hooks.sh:25-34`; `.beads/hooks/pre-push:4-28`), but the verifier reads Git's ref records only from inherited stdin (`scripts/pre-push:16-20`). If an earlier Beads-chained hook reads that stream, the verifier's loop executes zero times and exits **0**, without configuring, building, or testing anything. Beads 1.0.3 passes stdin through to an executable `.old` chained hook ([upstream `cmd/bd/hooks.go`](https://github.com/gastownhall/beads/blob/v1.0.3/cmd/bd/hooks.go#L1081-L1117)); this checkout currently has no `pre-push.old`, so the bypass is a **chaining counterfactual**, not an observed current push. I reproduced it in a temporary copy of the committed regression fixture by making its mock Beads hook drain stdin: the combined hook returned success with a `BEADS` trace and no `CONFIGURE`/`BUILD`/`CTEST`. The committed fixture's Beads mock only writes a trace (`scripts/test-pre-push.sh:15-20`), so it misses this case. Preserve/replay the ref list across hook stages and add the consuming-hook regression before relying on this as a fail-closed gate.
2. **Blocking — zero registered tests pass.** `scripts/pre-push:56-59` treats bare `ctest --output-on-failure` exit 0 as proof of tests. CTest exits 0 with `No tests were found!!!` (verified in an empty temporary build directory). The regression mock simply returns zero unless `FAIL_STAGE=test` (`scripts/test-pre-push.sh:54-59`); it never models missing tests. Require at least one registered test (for example, CTest's no-tests-as-error mode) and test that case. This is distinct from existing intentional CTest skips, which remain outside this hook's proof.

### Correct behavior, limits, and recommendation

The pushed local OID—not the caller's dirty checkout—is materialized by detached worktree (`scripts/pre-push:26-30`), and the fixture checks that source distinction (`scripts/test-pre-push.sh:32-47`). Configure/build/explicit nonzero CTest results propagate under `set -euo pipefail`; the fixture verifies these failures, Beads nonzero, and direct Groundhog/schema/CI dependency triggers (`scripts/test-pre-push.sh:62-115`). A temporary real Git fixture confirmed that `worktree remove --force` removes a worktree with an initialized submodule, but the committed test has **no submodule** and does not prove the actual `nsync`/`nostrdb` network/init path. The hook initializes those two direct gitlinks (`scripts/pre-push:28-32`), not nostrdb's nested `deps/secp256k1`; current CMake also finds system secp256k1, so that omission is a portability caveat, not a demonstrated bypass. Cleanup suppresses a failed worktree removal (`scripts/pre-push:8-13`), which could leave stale worktree metadata if removal fails.

The `BUILD_GROUNDHOG` predicate covers Groundhog itself, known direct source dependencies, its copied schema, and workflow (`scripts/pre-push:34-52`), with ON/OFF fixture checks. It is not a complete transitive-dependency proof (for example, `libgo/` and `libjson/` are absent); the default build still checks those libraries, but may miss Groundhog-only integration after their changes. `BUILD_GROUNDHOG` remains optional, so headless/GUI skips are not live Groundhog acceptance. `bash -n` for the hook, installer, and regression script; `bash scripts/test-pre-push.sh`; and `git diff --check 0e2e90ec..36c015bd` passed. No real full build/CTest or remote push was run for this review. **No component version bump** is warranted for hook/test-only changes.
