- **Envelope fuzz ownership — real fix, not a sanitizer mask.** The former harness stack-allocated `NostrEnvelope` and passed its address to `nostr_envelope_free`, which always frees the envelope allocation (`libnostr/src/envelope.c:712-748`). The replacement uses the production `nostr_envelope_parse` heap-owning path and frees its result, including NULL safely (`tests/fuzz_envelope_deserialize.c:8-19`; `libnostr/src/envelope.c:663-709`). The workflow now points at the envelope corpus, not filter seeds (`.github/workflows/nostrc-ci.yml:119-129`; `tests/CMakeLists.txt:200-231`). The `NOTICE` and `REQ` seeds exercise relevant envelope forms. **Coverage caveat:** `tests/fuzz_seeds/envelopes/event_with_subid.json:1` lacks signed-event `id`, `pubkey`, `tags`, and `sig`; the strict EVENT path rejects it (`libnostr/src/envelope.c:373-398`; `libnostr/src/event.c:415-418`). It is useful as a rejection seed but does not seed the accepted signed-EVENT path. Add a genuinely signed EVENT seed when extending this corpus. The baseline Actions short-fuzz failure was masked at the job level, and the step still has `continue-on-error: true` (`.github/workflows/nostrc-ci.yml:119-121`), so fuzz findings are **not** a CI gate; do not treat a green workflow as proof of clean fuzzing.
- **Marmot MDK fixture/XFAIL — correct, with assertions restored to the gate.** `admins` is an array of 32-byte elements. The previous `admins + 32` advanced 1,024 bytes after allocating only 64; the new count-based allocation and indexed initialization stay in bounds (`libmarmot/tests/test_interop.c:1062-1067`; `libmarmot/src/extension.c:154-155`). No assertion or sanitizer was weakened by these commits.
