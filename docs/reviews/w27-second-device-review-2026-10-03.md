# W27 slice B independent review — 2026-10-03

**Verdict: CHANGES-REQUIRED.** Reviewed `dfa66138`, `cc8a3ffc`, `30734f58` against `3b6bcc57` in `/tmp/rv-w27-second-device` (`review/w27-second-device`). This cannot be used as the nostrc-7gx7 two-device release evidence yet.

## Findings

1. **Blocker — the bus probe rejects a healthy session bus.** `gnome/groundhog/src/main.c:246-259` sends only the initial NUL byte and waits for a reply. A live `dbus-daemon` waits for an `AUTH ...\r\n` command; it does not answer that byte alone. Against the answering `/tmp/ghsmoke/bus.sock`, a direct socket check received nothing for five seconds, and the new `groundhog --smoke` logged the fallback. Thus every ordinary launch on that bus waits five seconds, sets `DBUS_SESSION_BUS_ADDRESS=unix:path=/dev/null`, and loses the signer, notifications, dconf/portal access, and single-instance registration. The Linux smoke gate's `groundhog-background/no9-process-service` failed even on serial rerun: that test waits for the default bus name, which NON_UNIQUE no longer owns (`gnome/groundhog/tests/app/test_background.c:1467-1479,1560-1569`). Complete a real, bounded D-Bus authentication/connect, and test both a responding bus and a stalled one. The current in-app banner at `gnome/groundhog/src/ui/gh-status.c:148-149` says “No session bus” and does not mention notifications, despite the bus existing and the promised notice.

2. **Blocker — the documented `--instance NAME` command does not work.** `gnome/groundhog/src/main.c:79-88,437-442` shifts some `argv` entries but never writes the new NULL terminator or returns the reduced `argc`. For `groundhog --instance dev2`, the original `--instance` reaches GApplication, which exits 1 with `Unknown option --instance` (reproduced). With `--instance dev2 --smoke`, it exits 1 with `Unknown option --smoke`. Accept an `int *argc`, remove exactly the option pair including the terminator, and test the CLI form in a release-like process. Also fail closed on an invalid or missing name instead of silently launching the default profile (`main.c:96-103`), where the user may unknowingly open the default store. The strict name character whitelist itself prevents path traversal and shell metacharacters.

3. **Blocker — the “two-instance acceptance” test does not launch Groundhog.** `gnome/groundhog/CMakeLists.txt:1820-1856` builds a separate headless `groundhog-test-harness`; `gnome/groundhog/tests/app/test_two_instance_acceptance.c:145-159,223-239` spawns that executable and calls `GhMlsService` directly via D-Bus. The harness directly sets account settings, supplies an identity lister and deterministic store key, creates its own data directories, and calls service methods (`gh-test-harness.c:429-555`). It never executes production `main.c`, GTK onboarding/group UI, the real signer identity selection, Secret Service store-key path, named-instance XDG handling, or production notifier/autostart. Empirically the acceptance test still passes with `GROUNDHOG_BIN=/bin/false`; it is valuable service integration coverage, but not the promised real-app acceptance or nostrc-7gx7 evidence. Keep it under an accurate name and add a test that drives two actual `groundhog` processes through UI/actions. The test-only control interface is confined to the separate harness target with `GH_MLS_TEST_HOOKS`; no `TestControl` string was found in the production binary, and no private key is returned by its methods.

4. **High — the manual second-device launcher cannot select its second signer.** `/tmp/ghsmoke/start2.sh:26-34` starts another daemon with `NOSTR_SIGNER_BUS_NAME=org.nostr.Signer.dev2`, but that variable is not implemented. `apps/gnostr-signer/daemon/main_daemon.c:308-317` always owns the compiled `ORG_NOSTR_SIGNER_BUS` (`org.nostr.Signer`), and Groundhog always calls that fixed name (`gnome/groundhog/src/app/gh-account-controller.c:5`; `src/identity/gh-signer.c:7`). The second daemon loses NAME_TAKEN while both Groundhog instances see the first signer/key. `pgrep -f` matches command lines, not the proposed key environment variable, so it does not make this safe. `/tmp/ghsmoke/throwaway2.hex` exists, but the launcher cannot use it as written. Fix the signer/client name contract or load both keys into one supported signer and verify that each instance selects a distinct identity before the manual run. I did not run `start2.sh` or the checklist.

5. **High — named-instance background startup does not follow the instance.** `gnome/groundhog/src/app/gh-background.c:686-688` writes autostart under the overridden, nested `XDG_CONFIG_HOME/.groundhog-instances/NAME/autostart`, which a normal desktop session does not scan. The generated entry's `Exec` has no `--instance` or `GROUNDHOG_INSTANCE` (`gnome/groundhog/data/org.nostr.Groundhog-autostart.desktop.in:4`), and the installed D-Bus service still owns only `org.nostr.Groundhog` (`data/org.nostr.Groundhog.service.in:2-3`). Even if that entry were discovered, it would restart the default profile. Preserve default desktop/service behavior, but give named instances a discoverable, distinct autostart entry and correct launch arguments, or explicitly disallow background autostart for them.

6. **High — GSettings isolation is conditional, not guaranteed.** `gnome/groundhog/src/main.c:137-141` leaves any caller-supplied `GSETTINGS_BACKEND` untouched. With `GSETTINGS_BACKEND=dconf`, both named instances use the same fixed schema/path (`gnome/groundhog/src/app/gh-app-services.c:182-187`) on the same bus, so `current-npub`, relay lists, and settings can be shared despite separate XDG directories. The tests force `GSETTINGS_BACKEND=memory` (`CMakeLists.txt:633,1856`), so they do not validate the documented keyfile backend. Force an isolated backend/path for named instances or reject unsafe overrides, and test persisted settings across two real processes.

7. **Medium — the probe is not a universal five-second bound.** `gnome/groundhog/src/main.c:177-203` returns TRUE without probing valid `unix:abstract=` and TCP D-Bus addresses, so a stalled bus of those forms can still block in `g_application_run()` (`main.c:496`). Even for Unix paths, the two `poll()` calls each use the full five seconds (`main.c:230-257`), and a response to this preliminary socket says nothing about the subsequent GLib connection. Use one deadline covering the actual bus connect/authentication and a deterministic fallback for every supported address.

8. **Medium — the automated checklist does not assert several gate outcomes.** `gnome/groundhog/tests/app/test_two_instance_acceptance.c:319-384` calls remove, immediately re-adds, then leaves without verifying that B observed removal, that messages work after re-add, or that A observed B leave. After restarting both processes, it checks only A's group and message history, not B's. `/tmp/ghsmoke/TWO-DEVICE.md:49-64` asks for those observations, but the automated test cannot substitute for them until it asserts them. The test's `AcceptContact` method also directly opens a conversation model rather than exercising the user acceptance path (`gh-test-harness.c:795-811`).
