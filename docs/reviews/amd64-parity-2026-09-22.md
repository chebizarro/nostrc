## 4. Packaging pre-phase — three build shapes on amd64

Three build shapes (Track A definition of "full tree": libhanami / libmarmot /
nostr-gobject / nostr-gtk / marmot-gobject / relayd + nostrdb + GLib, apps and
CTest scope off — matches the aarch64 verification recorded in
`31d804fb chore(pkg): pre-phase A -- ABI/naming hygiene for core libs`).

All three: `-DCMAKE_INSTALL_PREFIX=/usr -DCMAKE_INSTALL_LIBDIR=lib/x86_64-linux-gnu`.

### (a) Full-tree STATIC — `RelWithDebInfo`

```
cmake -S <src> -B /tmp/amd64/build-static -G Ninja \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo -DBUILD_SHARED_LIBS=OFF \
  -DBUILD_APPS=OFF -DBUILD_TESTING=OFF \
  -DENABLE_NOSTR_HOMED=ON \
  -DNOSTR_HOMED_ENABLE_SMB=ON -DNOSTR_HOMED_ENABLE_CTL=ON \
  -DNOSTR_HOMED_ENABLE_AUTH_CORE=ON -DNOSTR_HOMED_ENABLE_IDENTITY_CORE=ON \
  -DNOSTR_HOMED_ENABLE_DOMAIN_CONFIG=ON -DNOSTR_HOMED_ENABLE_NSS=ON \
  -DNOSTR_HOMED_ENABLE_AUTH_RUNTIME=ON -DNOSTR_HOMED_ENABLE_PAM=ON \
  -DCMAKE_INSTALL_PREFIX=/usr -DCMAKE_INSTALL_LIBDIR=lib/x86_64-linux-gnu
cmake --build /tmp/amd64/build-static -j 8
```

**Result**: 771/771 targets built in ~26 s. `.a` artifacts land at expected
paths (`libnostrgo.a`, `libnostr.a`, `libnostr-json.a`, `libhanami.a`,
`libmarmot.a`, `libnostr-gobject-1.0.a`, `libnostr-gtk-1.0.a`,
`libmarmot-gobject-1.0.a`).

### (b) Full-tree SHARED — `BUILD_SHARED_LIBS=ON`

Same flags as (a) with `-DBUILD_SHARED_LIBS=ON`.

**Result**: 778/778 targets built in ~27 s. Shared libraries installed to
`$DESTDIR/usr/lib/x86_64-linux-gnu/`.

## 7. amd64-specific fixes committed on this branch

One class of fix was needed. GCC (13.3 here, and any GCC — this is not
`x86_64`-specific per se, but it only fires when GCC compiles these files;
the aarch64 harness never hits them because `-DBUILD_APPS=OFF
-DBUILD_NOSTR_GTK=OFF` scopes them out, and the aarch64 pre-phase full-tree
verification also had `BUILD_TESTING=OFF`):

- `nostr-gtk/tests/test_bind_latency_budget.c`
- `apps/gnostr/tests/test_real_bind_latency.c`
- `apps/gnostr/tests/test_event_item_txn_budget.c`

Each used `defined(__has_feature) && __has_feature(address_sanitizer)` on a
single `#if` line. GCC macro-expands both operands of `&&` before
short-circuiting, so a bare `__has_feature(…)` token errors out even when
`defined(__has_feature)` is false. Applied the same shim used in
`nostr-gobject/src/nostr_simple_pool.c` (commit `82df3e77`):

```c
#ifndef __has_feature
#  define __has_feature(x) 0
#endif
```

Confirmed by re-running shape (a) after the fix: 771/771 targets, clean.

## 8. Deltas vs aarch64 baseline

Nothing amd64-specific reproduces beyond the three `__has_feature` sites
above. All SONAMEs, install paths, and the headless `nostr-homectl` NEEDED
set match the aarch64 evidence bit-for-bit (SONAME strings identical; ELF
class differs as expected — `ELF64 x86-64` vs `ELF64 aarch64`).

### Pre-existing full-tree defects surfaced but out-of-scope for this track

These reproduce identically on aarch64 (verified by code inspection — the
symptoms are `#include`s / target references that don't depend on the target
architecture). They surface only when `BUILD_APPS` or `BUILD_TESTING` are
turned back on with the current default option matrix, so they fall outside
Track A / B / C's verified surface and outside the scope of the amd64 parity
task. Filing follow-ups is recommended:

- `apps/gnostr` target `gnostr-test-keystore` `#include`s
  `<nostr-gobject-1.0/gnostr-app-bridge.h>` (via `src/util/keystore.h`) but
  does not link `nostr_gobject`, so its `PUBLIC` include directory does not
  propagate. Same story for a handful of adjacent `gnostr-test-*` targets.
- `nostr-gtk/tests/test_nostr_gtk_*` link `-lgnostr-widget-test-support`
  (defined in `apps/gnostr/CMakeLists.txt`) but the outer `BUILD_TESTING`
  block is not guarded on `BUILD_APPS`.
- `nostr-gtk/tests/test_note_card_measure.c` `#include`s
  `<nostr-gobject-1.0/gnostr-identity.h>` but the target does not link
  `nostr_gobject`.

## 9. Reproduction

From this checkout on the workstation:

```
# 1. Harness parity
VM_SSH=gnome-dev SKIP_DEPS=1 VM_WORKDIR=nostrc-ci bash scripts/vm-linux-ci.sh

# 2. Three build shapes -- on gnome-dev
ssh gnome-dev bash -s <<'REMOTE'
set -euo pipefail
SRC=$HOME/nostrc-ci/src
git -C "$SRC" submodule update --init --recursive third_party/nostrdb
for shape in static shared release; do
  case "$shape" in
    static)  extra="-DBUILD_SHARED_LIBS=OFF -DBUILD_APPS=OFF -DBUILD_TESTING=OFF -DENABLE_NOSTR_HOMED=ON -DNOSTR_HOMED_ENABLE_SMB=ON -DNOSTR_HOMED_ENABLE_CTL=ON -DCMAKE_BUILD_TYPE=RelWithDebInfo" ;;
    shared)  extra="-DBUILD_SHARED_LIBS=ON  -DBUILD_APPS=OFF -DBUILD_TESTING=OFF -DENABLE_NOSTR_HOMED=ON -DNOSTR_HOMED_ENABLE_SMB=ON -DNOSTR_HOMED_ENABLE_CTL=ON -DCMAKE_BUILD_TYPE=RelWithDebInfo" ;;
    release) extra="-DCMAKE_BUILD_TYPE=Release -DCMAKE_C_FLAGS_RELEASE='-O2 -g -DNDEBUG' -DENABLE_NOSTR_HOMED=ON -DLIBNOSTR_WITH_NOSTRDB=OFF -DNOSTR_HOMED_ENABLE_SMB=ON -DNOSTR_HOMED_ENABLE_CTL=ON -DBUILD_APPS=OFF -DBUILD_NOSTR_GTK=OFF -DBUILD_NOSTR_GOBJECT=OFF -DBUILD_LIBHANAMI=OFF -DBUILD_LIBMARMOT=OFF -DBUILD_MARMOT_GOBJECT=OFF -DSIGNET_ENABLE=OFF" ;;
  esac
  rm -rf /tmp/amd64/build-$shape
  cmake -S "$SRC" -B /tmp/amd64/build-$shape -G Ninja $extra \
    -DCMAKE_INSTALL_PREFIX=/usr -DCMAKE_INSTALL_LIBDIR=lib/x86_64-linux-gnu
  cmake --build /tmp/amd64/build-$shape -j 8
done

# SONAME + install-path evidence
DESTDIR=/tmp/amd64/stage cmake --install /tmp/amd64/build-shared
readelf -d /tmp/amd64/stage/usr/lib/x86_64-linux-gnu/libnostr.so.1.0.0 | grep SONAME
readelf -d /tmp/amd64/build-shared/gnome/nostr-homed/nostr-homectl | grep NEEDED
REMOTE
```
