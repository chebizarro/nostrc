## Findings

1. **Medium — stale PID can kill an unrelated process; restart can overlap processes.** `scripts/vm/w27-session.sh:18,75-78` treats any live PID in the persistent run directory as Groundhog, sends it SIGTERM, deletes the PID file, then immediately launches another instance without waiting for exit. After a VM restart or long-running reuse, PID recycling can make `restart-groundhog` kill an unrelated user process. If Groundhog is slow to exit, old and new instances race for the same profile/D-Bus name; a mock process that ignored TERM left both old and new PIDs alive after this action. Validate the PID's executable/ownership and wait for the old instance to exit (bounded timeout) before replacement; never signal a PID based only on `kill -0`.
2. **Medium — run identifier/path is not confined.** `scripts/vm/w27-session.sh:6-12,42,77` and `scripts/vm/w27-screenshot.sh:4,8-11` accept an unchecked `W27_RUN_ID` and arbitrary `W27_RUN_DIR`, then create directories/files and chmod/remove paths under it. For example `W27_RUN_ID=..` resolves the default run directory to `$HOME`, where `start` changes its mode to 0700 and writes runtime/data/key files. `W27_RUN_DIR=/tmp/ghsmoke` also directs writes there, contrary to the explicit no-writes constraint. Require a single safe timestamp-like path component, reject the prohibited path, and guard/canonicalize overrides before any mutation.
3. **Low — owner lab endpoint is disclosed for integrator decision.** `docs/reviews/w27-two-device-vm-run-2026-10-03.md:9` publishes the VM username, private IP and peer hostname. The IP is the already documented UTM lab VM in `nostrc-ngvb`, not a secret key, but it is still private-lab addressing; the integrator should explicitly decide whether it belongs in a committed report (or redact it). No nsec, private-key block, SSH key, or apparent 64-hex secret was found in the four added files. The 64-hex value on report line 25 is identified as a container image digest; other IPs are loopback.
4. **Nit — one screenshot citation does not itself show the claimed failure.** `docs/reviews/w27-two-device-vm-run-2026-10-03.md:47` names `amd64/a-media-satellite-outcome.png`, which shows the account-upload consent dialog, not the 401 outcome. `amd64/groundhog.log:1194` *does* show the 401, so the failure conclusion stands; cite the log as primary evidence or a final error screenshot if available.
