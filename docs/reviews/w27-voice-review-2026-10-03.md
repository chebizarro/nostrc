# W27 slice A voice-message review — 2026-10-03

**Verdict: CHANGES-REQUIRED.** Reviewed `groundhog/w27-voice` at `e5348de9` (seven commits since `3b6bcc57`) in an isolated `/tmp/rv-w27-voice` worktree. The wire-level MIME approach can interoperate, but the shipped receive UI cannot reach playback, recorded plaintext survives completion, and the claimed MDK voice test is neither compiled nor registered. No code changes were made to the reviewed branch.

## Findings (ordered by impact)

1. **Blocker — downloaded voice messages never become playable.** `gnome/groundhog/src/ui/gh-voice-bubble.c:273-287` invokes the provider's download callback but neither observes the transfer nor calls `gh_voice_bubble_load_audio()` (`:485-525`). There is no production call to `gh_voice_bubble_load_audio()` anywhere in the tree; `gh_message_row` hides the normal attachment card for audio at `gnome/groundhog/src/ui/gh-message-row.c:437-459`. A recipient taps Download, the transfer can reach READY, but the bubble remains in `download_box` with no player, waveform, duration, or play controls. The same occurs after restart even if cached plaintext is ready. Wire that READY/error/cancel state to the bubble and add an end-to-end UI test through the real transfer provider.

2. **Blocker — plaintext recordings persist and are not securely handled as promised.** `gnome/groundhog/src/media/gh-voice-recorder.c:90-93` skips temp cleanup in `DONE`; `gnome/groundhog/src/app/gh-attachment-ui.c:742-752` reads bytes and finalizes the recorder, leaving its completed Ogg file in `g_get_user_cache_dir()/groundhog/voice-tmp` indefinitely, even after send or offer cancellation. Cancel calls only `g_unlink()` (`gh-voice-recorder.c:160-166`), not the charter's zeroing (`docs/designs/groundhog-privacy-ux-charter-2026-09-28.md:700-705`). `filesink` creates with process umask, not explicit `0600`; I reproduced `0644` with umask `022` inside a `0700` directory. `gh-attachment-ui.c:767-771` ignores directory-creation failure and does not validate an existing directory's permissions. The linter exception at `gnome/groundhog/tests/check_privacy.py:167-173` claims immediate wipe/finalize cleanup that the code does not perform. Use a checked private location, exclusive `0600` creation, and guaranteed cleanup after the bytes are copied (including errors); make the charter and exception truthful.

3. **High — the MDK 0.11 voice test is dead, uncompilable, and asserts the wrong outgoing name.** `gnome/groundhog/CMakeLists.txt:1994-1998` tests `TARGET groundhog-voice` before defining that library at `:2672-2684`, so the voice case is compiled out; `:2067-2070` also omits `white-noise-voice` from the CTest case loop. Direct `-p /groundhog/mdk011-interop/white-noise-voice` therefore reports “no case matched.” A reviewer-only compile with `GROUNDHOG_HAVE_VOICE=1` found malformed C string literals and a nested-comment warning at `gnome/groundhog/tests/mls/test_mdk011_interop.c:1641,1675-1676,1727-1733`. After repairing only that temporary test source, the live case failed at `:1728`: Groundhog's privacy-neutralized outbound `imeta` says `filename file.ogg`, not `voice.ogg`. Changing that test expectation to the actual filename let the bidirectional MDK 0.11 case pass. Move voice target creation before the conditional, register the case, fix the literals, and assert the intended neutralized name.

4. **High — the “White Noise voice” fixture is generic, non-playable Ogg media, not White Noise's recorder output.** The test invents a 47-byte Ogg-like sequence with a fake CRC (`gnome/groundhog/tests/mls/test_mdk011_interop.c:1619-1635`) and sends it through MDK's generic `send_media` command as `audio/ogg` (`:1670-1677`). Actual [White Noise Android `VoiceRecorder`](https://github.com/marmot-protocol/whitenoise-android/blob/73aaf05039f4a2d957800f3f06eeac2eab374d55/app/src/main/java/dev/ipf/whitenoise/android/audio/VoiceRecorder.kt#L9-L17) uses AAC-LC in MP4; its [MIME constant is `audio/mp4`](https://github.com/marmot-protocol/whitenoise-android/blob/73aaf05039f4a2d957800f3f06eeac2eab374d55/app/src/main/java/dev/ipf/whitenoise/android/audio/VoiceRecorder.kt#L131-L138) and [send path names a `.m4a` file](https://github.com/marmot-protocol/whitenoise-android/blob/73aaf05039f4a2d957800f3f06eeac2eab374d55/app/src/main/java/dev/ipf/whitenoise/android/ui/conversation/ConversationMediaSender.kt#L400-L430). Both clients do classify received `audio/*` as audio/voice (`gh-voice-meta.c:6-12`; [White Noise receiver](https://github.com/marmot-protocol/whitenoise-android/blob/73aaf05039f4a2d957800f3f06eeac2eab374d55/app/src/main/java/dev/ipf/whitenoise/android/media/MediaReferenceSupport.kt#L59-L63)), so this is a coverage/claim defect, not proof of an incompatible wire format. Add a real `audio/mp4`/AAC receive vector and valid playable Ogg/Opus outbound vector; assert UI playback, not just decrypted byte equality.

5. **High — missing runtime GStreamer plugins can make playback crash; the Linux image installs only development libraries.** `gnome/groundhog/src/media/gh-voice-player.c:289-303` passes `NULL` for `gst_parse_launch()`'s error, assumes any non-NULL result is a `GstBin`, and dereferences the `appsrc` lookup without checking it. With only the `appsrc` plugin available, an ASAN/UBSAN probe of `gh_voice_player_load()` exits `133` at a fatal `gst_bin_get_by_name: GST_IS_BIN` critical. With no plugins it reports a graceful error; partial installation is the crashing case. `scripts/linux-ci.Dockerfile:18-21` and hosted CI install `libgstreamer1.0-dev` plus `libgstreamer-plugins-base1.0-dev`, but the built image contains only core elements, not `appsrc`, `opusenc`, `oggmux`, `decodebin`, `scaletempo`, or `autoaudiosrc`. `scripts/check-linux-ci-packages.py` confirms the lists agree, but does not check runtime elements. Validate the complete pipeline and all required factories at runtime, and install/test the runtime plugin packages in CI and distribution.

6. **High — no received waveform is computed.** `gh_voice_player_load()` accepts a waveform but only retains a supplied pointer (`gnome/groundhog/src/media/gh-voice-player.c:266-273`); `gh_voice_bubble_load_audio()` always supplies `NULL` (`gnome/groundhog/src/ui/gh-voice-bubble.c:500-525`). There is no call from the receive path to `gh_voice_waveform_from_pcm()`, and `waveform-ready` is never emitted by the player. Once finding 1 is fixed, received clips still show only the fallback line, contrary to the requested waveform. Compute a bounded waveform from decoded audio after explicit download, or display an honest no-waveform state.

7. **Medium — microphone permission and availability claims are not implemented.** The capture pipeline directly uses `autoaudiosrc` (`gnome/groundhog/src/media/gh-voice-recorder.c:312-325`); there is no portal permission request in the voice path, although the charter says there is (`docs/designs/groundhog-privacy-ux-charter-2026-09-28.md:694-700`). `gh-attachment-ui.c:1128-1130` unconditionally enables the mic, while `update_can_attach()` calculates whether the current conversation can actually send (`:189-199`). A user can record in an unsupported conversation and then get “Files can't be sent”; on a portal-managed desktop the capture may fail late rather than present the promised permission flow. Gate the button on sendability and provide a tested portal/native permission path where supported.

8. **Medium — recording and playback controls miss promised keyboard/screen-reader behavior.** The only composer key handler handles Enter (`gnome/groundhog/src/ui/gh-composer.c:275-319`); no Escape cancellation or swipe/long-press controller is installed despite the overlay/charter promise (`data/ui/gh-composer.blp:232-235`, charter `:700-703`). `gnome/groundhog/src/ui/gh-voice-bubble.c:205-218` changes the play button's tooltip but not its static accessible label (`data/ui/gh-voice-bubble.blp:95-103`), so a screen reader still announces “Play voice message” while it is playing. The speed button's accessible label likewise never announces the selected speed. Add keyboard/touch behavior and update accessible state/labels; test with actual actions, not only widget construction.

9. **Medium — playback cannot replay after EOS and speed selection before playback does not apply.** EOS calls `gh_voice_player_stop()` (`gnome/groundhog/src/media/gh-voice-player.c:219-222`), which destroys the pipeline (`:345-354`); the next Play action is a no-op because `gh_voice_player_play()` requires a pipeline (`:318-326`). `gh_voice_player_set_speed()` applies its seek only while already PLAYING (`:392-410`), so selecting 2× before Play still starts at 1×. Reload/re-preroll for replay and apply the selected rate when starting.

## Independent re-review addendum — `e4706624` (2026-10-03)

**Final verdict: CHANGES-REQUIRED.** The four remediation commits (`33e91772`, `6707c1e1`, `b7e7fc82`, `e4706624`) fix and exercise the ordinary paths behind the nine original findings. One remaining privacy failure on abnormal termination needs a fix before this feature lands. This review used a new `/tmp/rv-w27-voice-independent` worktree, not the earlier review worktree; the prior review commit was rebased cleanly onto `e4706624` there. No reviewed source was committed by the reviewer.

### Remaining finding

1. **High — an abrupt exit leaves a plaintext voice recording in persistent cache.** `gnome/groundhog/src/app/gh-attachment-ui.c:770-774` chooses `g_get_user_cache_dir()/groundhog/voice-tmp`; `gnome/groundhog/src/media/gh-voice-recorder.c:390-399` creates the Ogg there. Wiping is only called by in-process lifecycle paths (`gh-voice-recorder.c:95-97,480-483,534-545`); there is no startup scan or cleanup for `gh-voice-*` files. A crash, SIGKILL, or power loss during recording or between EOS and handoff bypasses those paths and leaves private-message audio in persistent cache until external cache eviction. I verified this with a temporary executable linked against the reviewed `groundhog-voice` library: it started `audiotestsrc`, waited 250 ms, then called `_exit(0)` without finalization. A `0600`, 468,685-byte `gh-voice-*` file remained and began with `OggS`; the probe file was then removed. The new `/voice/recorder/private-wipe` test covers normal handoff, not process death. Use a nonpersistent/private recording location and recovery-time stale-file scrubbing, or avoid plaintext files with an in-memory GStreamer sink; add an abrupt-exit/restart test. The normal-path zero-and-unlink fix is real, but it does not close this at-rest privacy case.

### Resolution of the original nine findings

1. **Download → play: fixed.** The bubble observes transfer notifications and loads READY plaintext (`gh-voice-bubble.c:263-350`); the UI test exercises explicit download, READY, visible player, and play/pause. Removing the READY→`gh_voice_bubble_load_audio()` call made `groundhog-voice-ui` fail at `test_voice_ui.c:137` (player not visible).
2. **Normal-path plaintext handling: fixed, subject to the High finding above.** Recorder files are exclusive `0600` in a checked user-owned `0700` directory; successful copy, read failure, cancel, error, and finalization call best-effort zero-and-unlink. The canary test inspects both the directory and retained inode. Disabling post-copy cleanup made it fail at `test_voice.c:341`; disabling only the overwrite, while preserving unlink, made the retained-inode canary fail at `test_voice.c:353`. The charter and linter exception now correctly say zeroing is not secure deletion on CoW/snapshot media.
3. **MDK voice test registration/compilation: fixed.** CMake links voice after target creation, compiles the fixture path, and registers `white-noise-voice`. The live CTest case ran and passed with the private driver image tag; the outbound neutralized filename is correctly asserted as `file.ogg`.
4. **White Noise format and imeta: fixed.** A decodable AAC-LC/MP4 vector (`audio/mp4`, `.m4a`) replaces the fake Ogg header for receive. Groundhog sends valid Ogg/Opus and MDK opens the exact bytes. The test asserts no speculative duration/waveform in MDK 0.11 imeta; waveform is computed locally after download. This matches pinned [White Noise `VoiceRecorder`](https://github.com/marmot-protocol/whitenoise-android/blob/73aaf05039f4a2d957800f3f06eeac2eab374d55/app/src/main/java/dev/ipf/whitenoise/android/audio/VoiceRecorder.kt), its [send path](https://github.com/marmot-protocol/whitenoise-android/blob/73aaf05039f4a2d957800f3f06eeac2eab374d55/app/src/main/java/dev/ipf/whitenoise/android/ui/conversation/ConversationMediaSender.kt), and [Android's Ogg/Opus decoder support](https://developer.android.com/media/platform/supported-formats). The vector is format-equivalent, not a byte-for-byte device recording; Android device playback was not independently exercised here.
5. **Partial GStreamer installation: fixed.** Player and recorder check required factories and validate parsed pipeline shape before dereferencing it; CI image and hosted job install and inspect runtime codecs/demuxers. Removing the player's factory and parse-shape guards made `/voice/player/partial-plugins` fail in its subprocess (the unsafe path returned success instead of the required user-facing error). `scripts/check-linux-ci-packages.py` passes. Codec-specific absence still degrades through the asynchronous decoder error path rather than a tested factory check, but the crash path is closed.
6. **Received waveforms: fixed.** After explicit download, the player decodes bounded PCM to an 80-bar waveform; the AAC and Ogg fixture test checks nonzero samples, and the UI test waits for the waveform-ready accessible label.
7. **Microphone availability: partly deferred, not an unimplemented portal claim.** The composer is gated on attachment sendability. The charter now explains that there is no app-callable XDG microphone portal; platform audio policy or native macOS permission mediates capture. Native permission prompt/denial behavior remains manual QA (`nostrc-ach4`), not proven by these tests.
8. **Accessibility and cancellation: fixed.** The tests exercise Escape and swipe cancellation and assert changing play/speed labels and recording-duration accessibility text. They do not substitute for a manual screen-reader pass.
9. **Replay and preselected speed: fixed.** The player rebuilds after EOS; the test plays a real Ogg clip twice with speed selected before playback and observes applied 2× speed and no errors.
