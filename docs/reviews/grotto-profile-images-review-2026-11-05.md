## Owner-policy and regression checks

- **Bounded redirects — confirmed/static and executed:** `apps/grotto/src/grotto-profile-service.c:560-593` validates the original endpoint before cache/network work and each current/next endpoint before sending. The counter permits the initial request plus at most five followed redirects: six sends maximum per image, including cycles. Only 301/302/303/307/308 are followed; a sixth redirect, unsupported status, absent Location, parse failure or failed send exits. A 3xx without Location reaches the explicit break at `:584-585`; it is not treated as image bytes. No unbounded redirect recursion exists.
- **Every-hop URL policy — confirmed/static:** `endpoint()` at `:48-52` requires HTTPS for images and a parsed host, and rejects userinfo and fragments. The next URL is resolved against the current URL with `g_uri_parse_relative()`, preserving encoded path/query components (`:586-591`). Relative and scheme-relative destinations inherit the base scheme; explicit HTTP downgrade, WS/WSS, data and file schemes fail the same validator before contact. HTTPS with credentials or a fragment is also rejected. Dynamic tests cover HTTP downgrade and encoded relative resolution; the other rejected schemes, credentials/fragments, missing Location and a self-loop were source-verified, not separately network-injected.
- **Cancellation and limits — confirmed/static, with executed decoder coverage:** cancellation is checked before each send, passed to `soup_session_send()` and `read_stream()`, checked before writing the cache, and converted to a cancelled task result at worker completion (`:567-575,578,597-599,771`). The final 200 body still goes through the 5 MiB bounded reader and the PNG/JPEG/WebP-only decoder, with 8192-per-side and 24-megapixel limits (`:525-557,578,595`). Redirect response bodies never reach the decoder/cache. The existing decoder test rejects SVG, oversized bytes and an 8193-pixel image (`apps/grotto/tests/test-profile-integration.c:649-656`); redirected oversized bodies and mid-hop cancellation were not separately fault-injected. Network cancellation can still fall through to local cache reading, but cannot cause another send or return a successful cancelled task.
- **Original cache key — confirmed/static and executed:** image path construction hashes the unchanged original URL plus the identity (`grotto-profile-service.c:562-565`); only `current` changes across redirects. Setting-off/Tor follow-up fetches in the integration test retrieve both cached images using that original URL without new origin requests (`test-profile-integration.c:250-264`). No cache key is replaced with the CDN URL.
- **Redirect scope — confirmed/static:** NIP-11 still uses a separate request with `SOUP_MESSAGE_NO_REDIRECT` (`grotto-profile-service.c:180-188`); NIP-05 does likewise at `:679-693`. Neither calls `download_image()`. Blossom upload code and transport are unchanged by the scoped diff. There is no relay subscription/protocol change requiring a broader Nostr protocol audit; the image redirect loop is HTTP fetching, not relay polling.
- **Automatic loading — confirmed/static and executed:** the schema default is true (`apps/grotto/data/org.nostr.Grotto.gschema.xml:131-135`). The FETCH worker reads both preferences and calls `download_image()` for picture and banner with exactly `online && load_images` (`grotto-profile-service.c:726-742`). Off therefore means image-cache-only, not disabling metadata discovery. Tor makes `network` and `online` false, leaving saved metadata/images available without relay/image network access. Missing/bad image bytes yield a null texture or cached texture, not a blocking profile error. The real `SignerWindow` host callback still admits unlocked own/watch-only FETCH and dispatches to this service (`apps/grotto/src/ui/signer-window.c:847-864`).
- **No consent UI or approval auto-fetch — confirmed/static and executed:** both image-load buttons and their callbacks are removed from `gnome/grotto-panels/src/grotto-profile-view.c`; the deprecated action is explicitly rejected by the service (`grotto-profile-service.c:885-889`). SAVE retains/reuses supplied textures or reads cache only (`:747-758`); the approval dialog formats profile JSON/URLs into text rather than fetching them (`apps/grotto/src/ui/approval_dialog.c:1085-1097,1113-1121`). Integration checks automatic contact on initial profile load, no additional image contact with the preference off, no consent/error dialog, and unchanged contact count through Save/review (`test-profile-integration.c:480-489,534`). The design's approval-dialog never-auto-fetch rule remains intact.
- **Panels ABI/boundary — confirmed/static and executed:** the sole public-header change is formatting plus the deprecation comment (`gnome/grotto-panels/include/grotto-panels-0/grotto-panels.h:177-183`). Action values remain FETCH=0, SAVE=1, CHOOSE_AVATAR=2, CHOOSE_BANNER=3, LOAD_IMAGES=4, VERIFY_NIP05=5. No public enum member, declaration, exported symbol or struct member is removed/renumbered by this diff. Private view members/buttons are not public layout. The removed Grotto confirmation helper was not a panels API. No secret/policy field or evaluator is added to panels; no-secrets and Control1 tests pass. The new standard `AdwSwitchRow` has the requested short title and explanatory subtitle (`page-settings.c:193-201`), consistent with [GNOME writing guidance](https://developer.gnome.org/hig/guidelines/writing-style.html).
