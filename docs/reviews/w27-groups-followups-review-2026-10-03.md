# W27 slice D — independent review (2026-10-03)

**Verdict: CHANGES-REQUIRED** for `groundhog/w27-groups-followups` at `097beb39` (base `3b6bcc57`; commits `2170aba7`, `6abc8dc5`, `097beb39`). The successful-path implementation and interop tests are strong, but the new Group Info callback has a use-after-free path and the dual-slot publication does not establish the promised legacy-newer invariant under partial failure.

## Findings

1. **High — Group Info media update can call back into a destroyed dialog.** `gnome/groundhog/src/ui/gh-mls-group-info-dialog.c:312-344`. `action_update_media()` passes raw `self` as async user data, with no reference or cancellable. If an admin presses **Update File Servers** and closes Group Info before the relay accepts (or an error returns), `on_media_updated()` calls `toast()`/`sync_media_policy()` on a disposed or freed dialog. The neighboring `change_done()` path instead uses `change_new()` to retain `self`, tracks `pending`, checks destruction, and unrefs in the callback. Use that lifecycle (and surface cancellation safely); test closing the dialog with the change in flight.

2. **High — a companion legacy KeyPackage is not guaranteed to be newer on *each* write relay.** `gnome/groundhog/src/mls/gh-mls-service.c:7130-7165,7191-7203,7619-7636`. Adopted and legacy are signed/published independently. Each slot is marked published on its *first* relay OK, and only `!summary->any_accepted` schedules a retry. With write relays R1/R2, if both accept adopted but R2 rejects/times out for legacy, R2's newest kind-30443 event remains adopted: a slot-blind MDK 0.8/0.9 reader selects it and fails parsing. If the companion signer is declined, `key_package_signed()` at lines 7244-7252 marks it failed without scheduling a retry, leaving the same gap. The lifecycle test checks both relays only when both accept; add per-relay failure/repair coverage. Treat the adopted/companion pair as a per-relay obligation, not an `any_accepted` success.

3. **High — the forced-publish flag survives a failed attempt and can suppress retirement on an unrelated later ACK.** `gnome/groundhog/src/mls/gh-mls-service.c:7068-7087,7184-7195,7244-7252,7619-7624`. `keep_old_keys` is set before the forced legacy sign/publish but cleared only by `key_package_confirm()` on an accepted event. If that sign is refused or every relay rejects, the flag stays true. Once the invitation is declined, a normal legacy retry/replacement can get an OK, but its `key_package_confirm()` consumes the stale flag and skips `marmot_key_package_confirm_published()`. Older private init keys then remain past the ACK-tied retirement point until another rotation or expiry. Tie the exception to the specific in-flight ref/attempt and clear it on every failure/cancellation path; test forced failure followed by an ordinary successful replacement.

4. **Medium — old legacy keys are not retired when the original hold ends.** `gnome/groundhog/src/mls/gh-mls-service.c:7071-7074,7142-7148,7540-7567` (decline recheck at `:6230-6243`). On a successful forced companion OK, the code skips libmarmot confirmation, clears `held`, clears the persisted hold start, and records the new publication cursor. If the pending invitation is then declined, `key_package_maybe_publish()` sees nothing due and does not retire the pre-companion key. It lives until a later rotation or its full lifetime (default 28 days), not the original seven-day hold cap/expiry margin. This also contradicts the service header's ACK-tied-retirement contract. Track deferred retirement and finish it when the invitation hold ends, without deleting the key before that point; assert post-decline retirement in `upgrade-companion-held`.

5. **Medium — Create's file-server consent copy is false for older-format groups and absent for an empty list.** `gnome/groundhog/src/ui/gh-mls-new-group-page.c:150-171,215-228` and `gnome/groundhog/src/mls/gh-mls-service.c:4587-4611`. `sync_media_notice()` displays “Pictures and files shared in this group will be stored on …” whenever the account has Blossom servers, even when `self->format` is legacy; `create_group_now()` installs the 0x800b policy only for adopted groups. Conversely, with the default empty Blossom list it hides the row entirely, although the resulting adopted group has no media policy and cannot set a group picture until an admin configures servers later. Make the notice format-aware and explicitly state the no-server outcome before Create. Cover both states in the New Group UI test.

## Addendum — re-review at `b627150c` (2026-10-03)

**Final verdict: APPROVE-WITH-NITS.** This supersedes the changes-required verdict above. Commits `0f54c59e` and `b627150c` resolve all five findings; I found no remaining blocker in the reviewed paths.

1. **Group Info callback (former High 1): resolved.** `gh-mls-group-info-dialog.c:313-386,1321-1330` now owns a cancellable, finishes the async result without dereferencing a dead dialog, and uses a weak reference plus the dispose/destruction checks before touching widgets. The GUI test closes the dialog with the relay OK held, verifies it is freed, then releases the OK. Reverting this fix makes the test fail at its pending-operation assertion.
2. **Legacy-newer invariant (former High 2): resolved on eventual relay recovery.** `gh-mls-service.c:7337-7365,7410-7449,7816-7846` persists a legacy repair obligation after a partial relay result or signer failure, clears the publication cursor, and retries despite an invitation hold. The partial-relay test checks both relays' newest format after restart; the signer tests cover denial before and after adopted confirmation. Disabling partial-relay repair makes its test time out; reverting the signer-failure recovery makes both signer tests time out.
3. **Failed forced publish (former High 3): resolved.** `gh-mls-service.c:7337-7450` clears `keep_old_keys` on no-ACK and signer/publish failures. The forced-failure test then declines the invitation and verifies that an ordinary successful retry retires the old init key. Removing the no-ACK clear makes that assertion fail.
4. **Hold-bounded retirement (former Medium 4): resolved.** `gh-mls-service.c:7055-7229,7755-7783` persists the exact confirmed legacy ref and retires older init keys when the invitation ends or the original hold cap expires, including after restart. Disabling deferred retirement makes the post-decline assertion fail and the hold-cap test time out; both pass with the fix restored.
5. **New Group copy (former Medium 5): resolved.** `gh-mls-new-group-page.c:150-184` hides the media-policy claim for legacy groups and explicitly states the no-server outcome for adopted groups. The GUI tests cover both and fail when either branch is disabled.

**Nit — `VERSION_MANIFEST.md:230-232`:** A blank line separates the two new W27 decision rows from the existing decision table. Remove it so the rows remain inside that table; this does not affect the version decision. Libmarmot and Groundhog are still unreleased at `0.12.0`, so **no further version bump** is required.
