# W27 encrypted attachment delivery — 2026-10-04

**Release-gate item:** `nostrc-bz4g`. **Result:** PASS for the requested Groundhog→Groundhog attachment delivery on a suggested White Noise/MDK encrypted-media server. A 1.8 KiB PNG traveled in a NIP-17 DM from A to B and in a Marmot encrypted group in both directions. Each upload and recipient download returned HTTP 200; each recipient displayed the decrypted “W27” image. This is **not** a Groundhog↔White Noise interoperability test, and it does not by itself close the broader `nostrc-7gx7` gate.

## Defects and operational caveats

- **Live server-choice regression (`nostrc-5nln`):** on both VMs, initial first-use selection of divine was persisted and the sheet showed it, but Send returned to “Choose an Attachment Server” without a PUT. `amd64/20261004T100604Z-amd-divine-outcome.png` and `arm64/20261004T102323Z-arm-group-send-outcome.png` show the loop. Restarting only Groundhog retained the server and allowed the 200 PUTs above. This is a regression of closed `nostrc-1u9k`; it did not prevent end-to-end delivery after retry.
- **Relay migration (`nostrc-qaqh`):** moving an existing profile to the public discovery relay did not publish existing KeyPackages there. A direct EOSE query proved their absence before fresh-store onboarding and presence after. Old app stores were preserved under each VM's run directory rather than deleted.
- **Temporary forwarding dropout:** one SSH hop for the private group relay dropped after group creation, so B did not immediately receive A's first kind-445 media event. Restoring the hop led to normal backfill (two events before EOSE), download, and display. This was lab transport, not a Blossom refusal or client delivery claim.
- **Test-run qualification:** both rebuilt VMs passed compilation. Exploratory broad `ctest -R groundhog -LE gui` runs in this headless/live-app setup were **not clean**: the first invocation lacked the private display/session environment (A bus-probe exit 77; B GTK accessibility-bus SIGTRAPs); targeted bus-probe reruns with the private display/bus and `NO_AT_BRIDGE=1` passed 1/1 on each. A second broad run under that environment still had several GUI/two-instance failures, so this report does not claim a full VM CTest pass; `*-ctest*.log` records exact failures. A serial focused attempt stalled in `groundhog-mls-service` and was terminated; no test process remains. These suite attempts do not replace the direct UI/network delivery evidence above.
