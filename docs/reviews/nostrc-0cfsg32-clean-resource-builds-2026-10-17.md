## Change and ownership

`cmake/NostrcGtkResources.cmake` promotes the previously app-local policy into a
repository helper called independently by both component CMake files. The
library has no dependency on an application-owned helper or test. The helper:

- writes Blueprint outputs only under the caller's binary `data/` tree;
- creates nested output directories and makes generated files resource inputs;
- searches the binary tree before source fallbacks when compiling Blueprint;
- searches **only** source when reconfigured without the compiler, ignoring
  stale generated output;
- derives static inputs from the actual manifest, including source-only files;
- preserves manifest bytes/aliases/prefixes, output C filenames, Blueprint
  target names and install rules; invalid Blueprint still fails the build.

The application/library manifests are unchanged. Gnostr's Gtk.Spinner correction
and checked-in fallback from `c0d2a44f0` remain in force. Shared real-tool tests
are `tests/common/test_blueprint_resources.py`, registered as the existing
`gnostr-resource-build` and new `nostr-gtk-resource-build` CTests. The old
app-local helper/test paths are removed. The explicitly authorized additive
`apps/gnostr/TestInventory.cmake` describes `gnostr-resource-build` with
`OWNER gnostr`, no parent build target or display/private-bus requirement, and
absolute runtime inputs for itself, the app CMake file, shared test/helper and
full app data tree (the fixture copies and hashes every data file). B retains
the nostr-gtk descriptor delta and global input/metadata reconciliation; root
inventory and other component descriptors are unchanged.

Tests poison a tracked fallback in a disposable fixture, change a Blueprint
marker, check the actual linked resource, incrementally rebuild, remove a nested
generated output, change a source-only UI, reconfigure without the compiler,
and reject invalid Blueprint/wrong widget or inactive spinner. They hash all
fixture source bytes before/after. Both components enumerate every manifest
resource; the library's existing `xml-stripblanks` is compared as XML with only
whitespace/comment normalization, not treated as byte-preserving preprocessing.
The original dirty-checkout negative guard evidence remains independent.
