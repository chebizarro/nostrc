# Groundhog next release (0.12.0 alpha 6): Plan

Status: proposed, 2026-10-09. Target: Groundhog 0.12.0 alpha 6. Beads: file one epic with a child per execution-index item.

## Owner request (verbatim scope)
Bugs: reactions (emojis) don't work anywhere; still no historical NIP-29 messages; Note to self shows the raw pubkey in sidebar row and header.
Features: profile-picture "Load" as a right-click context menu on the avatar instead of a button; Markdown rendering of messages; tray menu items — "Open Groundhog" ↔ "Close Window" when the window is open, User Accounts, Launch on Login, Preferences, Update, File a NIP-34 issue; capture telemetry and make sanitized logs submittable with NIP-34 issues; copy-message button per bubble; i18n/l10n/a11y with Spanish, Portuguese, Dutch, German, French, Farsi, Arabic, Japanese.
Port/promote to nostr-gtk from gnostr: OG card; full NIP-21/18; media viewer; extra NIP-34 issue fields.


## 1. Summary

Groundhog 0.12.0 alpha 6 fixes reaction display and delivery across NIP-17, NIP-29 and Marmot, restores NIP-29 history, and gives self-only conversations the explicit title “Note to Self.” It also adds avatar-initiated picture consent, safe Markdown, copy-message, a dynamic tray menu, opt-in **local-only** diagnostics for public NIP-34 reports, eight initial translations, and accessibility improvements. Reusable OG, Nostr-reference, media-viewer and issue-field components move into an **app-independent nostr-gtk library**; Groundhog supplies its own consent, network and identity policies. This is a release-sized set of coordinated changes, not a single refactor: fix the three regressions at their existing seams, while making only the library split needed to avoid linking Groundhog to Gnostr internals.

Investigation evidence with file:line references is kept in **Appendix A**; this specification resolves the open questions it raised.

### Decisions that govern implementation

| Decision | Chosen behavior and rationale |
|---|---|
| Diagnostics versus charter P10 | Permit **off-by-default, local operational diagnostics only**. No analytics endpoint, crash uploader, automatic issue attachment, message-content logging or remote telemetry. Amend charter P10 to distinguish this from network telemetry; retain P3 and PD-10. |
| Diagnostic issue attachment | Append a **frozen, reviewed text appendix to the NIP-34 issue body**. Do not use Blossom: it would add another destination, upload identity and consent flow to a public-report action. A report cannot exceed the existing 16,000-byte body limit; never truncate silently. |

## 2. Current-state analysis and regression diagnosis

### Confirmed baseline

- **Reactions:** `GhMessageRow` opens the picker and emits `conversation.react`; `GhConversationView` resolves the target; `gh-app-services.c` dispatches to NIP-17, NIP-29 or Marmot. Receive paths converge through `GhReactionStore`, whose change signal reaches the conversation view. `GhMessageRow` currently creates `GhReactionBar` only when a count is positive. Persistence and pending-target handling already exist in `gh-store-reactions.c`; they must be reused, not replaced.
- **NIP-29 history:** `GhNip29Service` subscribes joined rooms and uses relay-scope paging; admitted events enter `gh-store-nip29.c`. The newest stored page becomes a conversation model; `has_older` and the near-top callback control earlier pages. A stored event absent from the in-memory model is deliberately not reinserted by live admission.
- **Note to Self:** the new-message dialog starts with zero peers. The conversation builder includes the account as the sole participant, but `GhConversation` removes self from `peers`. Contact title is then null, and `fallback_title()` derives a display name from the account key. Both sidebar and header consume `gh_conversation_get_title()`.
- **Tray/background:** `GnStatusNotifier` exposes fixed Open/Quit IDs and never emits `LayoutUpdated`. `GhBackground` owns the background hold, window-close disclosure, host autostart file and Flatpak portal. Preferences and report-issue actions currently require a window; account actions are window-scoped.
- **Issues/privacy:** `GhIssueDialog` snapshots title, body, relays and account before a public consent preview, then uses the shared NIP-34 builder, signer and `GhRelayPublish`. Its current charter explicitly promises no logs, attachments or device details. Groundhog has no log writer.
- **Content:** `GhLinkPolicy` already enforces safe raw links and NIP-21 mention links. Gnostr’s Markdown, OG and viewer code is app-coupled. `nostr-gtk` has a standalone core portion but its main archive still contains sources referencing Gnostr-private headers. Groundhog does not currently link it.

The reaction commits named in the existing alpha-6 plan are **suspects, not findings**. Similarly, “history not fetched” and “history stored but not listed” are different defects. Land reproductions before changing behavior.

### Diagnostic tests to land before fixes

| Regression | Instrumented reproduction and discriminating assertions |
|---|---|
| Reactions, all three backends | For each backend, send a reaction and receive a peer reaction against a stored target, then an early reaction whose target arrives later, then deletion/re-addition. Record picker selection → backend event construction/sign/publish → receive admission → `GhReactionStore` count/change signal → row bind/measure/visibility. Inject a known reaction directly into `GhReactionStore`: if the chip is absent, the failure is UI/binding rather than transport. Repeat after account switch and row recycling. Verify reaction and target belong to the exact same room. |
| NIP-29 history | With a scripted relay and an existing joined room, serve more than one 500-event page and a fresh live event. Record REQ filters, `EOSE`, relay-scope page cursor, store row count, `list_latest` result, `has_older`, near-top request and list insertion. Assert separately: (a) historical IDs reached admission, and (b) admitted IDs appeared in the timeline. Repeat with a restored cursor, same-second event ties, a disconnected relay and restart mid-page. |
| Note to Self | Build a zero-peer conversation through `GhNewMessageDialog`, restore it from storage, then switch accounts. Assert participant set contains only self; sidebar title, header title and accessible title all equal the localized “Note to Self,” never hex/npub. A normal one-peer conversation must retain its subject/contact/fallback precedence. |

**Backend/transport matrix:** run reactions for NIP-17, NIP-29 and Marmot on the local wire fixture, including outgoing and incoming paths; run NIP-29 history on both existing relay transports where supported. Ubuntu acceptance uses two named Groundhog instances and a real local relay. A backend failure must not be “fixed” only by forcing reaction-bar visibility.

### Fix contracts

- **Reactions:** keep `GhReactionStore` authoritative. On every row bind, account-store rebind and reaction-store change, derive the reaction bar from the current target ID and exact room; create/update/remove it deterministically, then update meta-row visibility and invalidate measurement. Ensure send dispatch reports failures without optimistic permanent chips. Pending reactions and tombstones keep the existing quotas/expiry; duplicate event IDs are idempotent, while a distinct re-add event is not masked by an older deletion. If instrumentation identifies a backend-specific malformed event or missing subscription, correct that sender/receiver as a separate tested fix.
- **NIP-29 history:** maintain **two distinct persisted per-room/per-relay positions**: newest/live cursor and oldest-history paging position, plus `history_complete` and `history_partial_reason`. An initial join fetches the newest page and continues EOSE-aware backfill up to the existing 16-page session budget; scrolling to Earlier Messages continues from the oldest position in later batches. Commit a position only after admitted page events and `EOSE`; a cancelled or failed page resumes from its prior position. `has_older` reflects stored rows **or** remotely uncompleted history, so the user can request more even if the local SQL page is exhausted. Deduplicate by event ID. If an overloaded same-second boundary cannot advance reliably with relay-supported filters, stop rather than skip silently, mark history partial and show “Some earlier messages may be unavailable.” Do not move the live cursor backward.
- **Note to Self:** `gh_conversation_get_title()` returns `_("Note to Self")` for a NIP-17 conversation whose participant set is exactly the active account, before subject/contact/fallback logic. This is a derived title, not a persisted override. Notify title consumers on account/model rebind.

## 3. Design

### 3.1 Message rendering, consent and actions

**Shared Markdown/reference layer.** Add a GTK-free `GnMarkdownDocument` and `GnNostrReference` API to the portable nostr-gtk target. The Markdown parser accepts bounded UTF-8 input and produces ordered block/inline tokens (text, emphasis, strong, code, heading, list, quote, separator, raw URL, Markdown link, Nostr reference); it does not emit Pango markup or fetch anything. Supported Markdown is precisely headings 1–6, emphasis/strong, inline and fenced code, ordered/unordered lists, blockquotes, separators, links and line breaks. Unsupported syntax remains literal text. Parsing invalid UTF-8 substitutes U+FFFD; depth and token count are capped so malicious nesting cannot stall a list bind. Reuse the existing `content_renderer` Nostr descriptor semantics and NIP-19 decoders; do not introduce a competing URI parser.

Groundhog’s formatter in `gh-link-policy.c` walks those tokens, escapes every text leaf before Pango markup, and applies existing `gh_link_policy_classify()` to link targets. Code spans are never linkified. A Markdown link with custom label renders as **label followed by its literal URL**; only that visible raw URL may be activated, preserving charter PD-3. `nostr:` references use the same offline decode and click routing as existing mentions; relay hints are displayed only in details, never automatically contacted. Parsing/formatting happens once per message body revision, not in every `GtkListView` bind: `GhConversationView` owns a main-context, account-scoped LRU of at most 256 results/2 MiB, keyed by message identity, body revision and display-name generation. Bodies over 4 KiB parse on a cancellable worker with immutable input; the row initially shows escaped plain text, and applies a result only if row binding generation still matches. Clear the cache on account switch. Parsing failures leave selectable escaped plain text.

**NIP-18.** Add a shared descriptor parser for kind 6 and 16 reposts and `q` references: original event ID/address, author when authenticated, optional relay hints, and raw referenced event if present. Gnostr’s timeline factory consumes it instead of its private extraction path. Groundhog uses it only when displaying a linked/quoted Nostr item in a message: a local match renders a compact card; a missing match is a reference placeholder with an explicit “Find on Relays” action. That action shows destinations and uses only the user’s configured discovery relays after confirmation. No automatic network lookup.

**Repost and quote authoring (owner decision 2026-10-09).** A rendered public-note card (resolved `note`/`nevent`/`naddr` reference, or a quoted item) gets **Repost** and **Quote…** actions. *Repost* builds kind 6 (kind 1 target) or kind 16 (any other kind, with `k`) carrying `e`/`a` + relay hint and `p` of the author, and the JSON of the original when it is held locally. *Quote…* opens a small public composer whose kind-1 note contains `nostr:nevent…` and a `q` tag (plus `p`). Both are **public** actions: a confirmation dialog shows the exact event, the account and the destination relays (the account's NIP-65 write relays; none → disabled with an explanation), mirroring the NIP-34 public-issue consent; signing goes through the account's signer (Grotto or remote), publishing through `GhRelayPublish` with the existing honest OK/partial reporting. Inserting a reference into the *current chat* (no public post) stays a separate “Share in Chat” action that only inserts the `nostr:` URI. The shared nostr-gtk descriptor/builder provides the event templates so Gnostr can reuse them.

**OG card and viewer.** Promote UI-only `GnOgPreviewCard` and `GnMediaViewer` into the portable library. The card owns URL/metadata/loading state and a cancellable; it exposes an explicit `load-requested` signal and `set_result()`/`set_error()` methods, but has **no HTTP client or Gnostr singleton**. The viewer owns zoom, pan, fit and gallery selection; it accepts already loaded `GdkTexture` items and signals `load-requested` for an unloaded item. Navigating a gallery never fetches automatically. Groundhog connects the signals to its existing preview/media consent and `GhNet` paths, validates HTTPS/redirects, byte and dimension limits from charter §2.1, and saves only through a user-selected portal file. Cancellation on unbind, dialog close, setting-off or account switch invalidates callbacks by generation. Gnostr adapters retain its existing `og_preview_widget_*` and `gnostr_image_viewer_*` API, injecting `GnostrMediaService` rather than keeping it inside shared widgets. Test standalone linkage without Gnostr symbols.

**Avatar action.** Remove the separate “Load Profile Picture” button from the message bubble. Attach right-click, long-press and keyboard Menu/Shift+F10 handling to the **avatar only**, stopping propagation so the bubble’s reaction-picker gesture remains unchanged. Show “Load Profile Picture” only when a URL exists and that image is not loaded; the action invokes the existing `conversation.show-preview` consent path and `GhPictureCache`. Avatar gets a focus target, accessible name and action description. Existing per-contact consent (`contacts.picture_allowed_at`, shared `GhPictureCache`) is kept unchanged: the owner accepted that model in earlier test drives, and own-account pictures still load without a prompt. *(Correction to the planning draft, which proposed clearing persisted grants and session-only consent — a behaviour change nobody asked for.)* Turning off `load-profile-pictures` cancels pending loads.

**Copy message.** Add one `conversation.copy-message` action carrying the bound message identity, not raw content in an action target. Resolve that identity against the current account/conversation generation, copy **what the bubble shows** as plain text (`gh_message_dup_display_text()` semantics for text, polls and replies); file messages (kind 15) show “Copy Link” instead, copying the file URL; withdrawn, expired and decrypt-failure rows hide both using the existing GTK clipboard pattern, and show “Copied” toast. Hide/disable for unavailable/decrypt-failure/local-status rows. A recycled row or stale action cannot copy another account’s message. Warn in accessible description that clipboard contents may be visible to other applications; Groundhog does not auto-clear the clipboard.

### 3.2 Tray, background and update

`GnStatusNotifier` becomes a generic dynamic flat-menu presenter. Add an application-supplied item model with stable integer ID, localized label, enabled/visible, optional separator and optional checked state; add `item-activated(id)` while preserving existing `activate` and `quit` signals/API for Gnostr. A changed snapshot increments `menu_revision`, emits `LayoutUpdated(revision, MENU_ROOT)`, and returns the same snapshot from `GetLayout`, `GetGroupProperties` and `GetProperty`. `AboutToShow` does not mutate state. Unknown IDs return protocol errors; clicks on hidden/disabled or stale items do nothing. `EventGroup` processes valid clicks in order and reports invalid IDs. `TextDirection` follows GTK’s current default direction. The notifier stays passive when no watcher exists.

Groundhog owns tray menu state and rebuilds it on window add/remove/visibility, `GhBackground` state, account availability and locale initialization:

1. **Open Groundhog** when no primary window is visible; **Close Window** when one is visible. Closing calls the normal `gtk_window_close()` path, including the one-time background disclosure.
2. **User Accounts** presents the window, then activates the existing `account.open` action.
3. **Launch on Login** is checked from the new setting and uses `gh_background_set_launch_on_login_async()`.
4. **Preferences** presents a window before invoking `app.preferences`.
5. **Update…** presents a deployment-specific handoff dialog.
6. **File a NIP-34 Issue…** presents a window before invoking `app.report-issue`.
7. **Quit Groundhog** remains available and stops background service.

The menu never claims account/prefs/report actions succeeded before a window exists. If background is off, Close Window may terminate the app and remove the tray; that is intentional.

Add `launch-on-login` (`b`, default `false`) while retaining `run-in-background`. On first startup after upgrade, if `launch-on-login` has no user value and `run-in-background` has a confirmed user value, copy that value once; a fresh profile stays launch-off. Enabling launch first enables background mode with its existing exposure explanation, then reconciles host autostart or Flatpak `RequestBackground(autostart=true)`. Disabling launch removes only autostart; it does not release the background hold. On portal denial or file failure, report the error and restore the prior launch setting; if the portal also denies background permission, disable background as current code does. Named instances expose Launch on Login disabled with an explanation. Serialize reconciliation so the latest user choice wins; cancellation on shutdown leaves persisted settings reflecting only confirmed state. Update charter §5.3 and tests for the split.

**Update…** has no background request. Build/package metadata records one channel: Flatpak, deb, rpm, Arch, Nix, or source/unknown. Flatpak offers “Open Software” via a registered `appstream:` URI handler, with textual Flatpak instructions if absent. Other channels say that Groundhog is updated by that channel’s package manager and offer “Open Software” only when an AppStream handler exists; source/unknown explains that the user must obtain a newer build from their original distributor. A failed URI launch keeps the dialog open with the textual fallback. No version comparison, HTTP URL or success claim is made.

### 3.3 Local diagnostics and public NIP-34 reports

Introduce `GhDiagnostics` as a process-owned service initialized **before ordinary application logging**, but inactive until `diagnostics-enabled` (`b`, default `false`) is explicitly set in Preferences. It accepts only typed allowlisted events; it must never write arbitrary `GLog` messages or raw `GError::message` strings. Its event shape is:

- `schema: 1`
- `day: YYYY-MM-DD` in local time, with **no per-message timestamp**
- `component`: one of `relay`, `store`, `signer`, `nip17`, `nip29`, `marmot`, `ui`
- `event`: a reviewed enum such as `connect_failed`, `publish_rejected`, `history_partial`, `render_fallback`
- `result`: `ok`, `retry`, or `failed`
- `count`: daily aggregate integer

No free-form field is accepted. Pubkeys, event/wrap/rumor IDs, group IDs, relay/website URLs or hosts, message text, file paths, signer payloads, keys, bunker URIs, IPs, full responses and stack traces are prohibited. A coarse app version, package channel, OS family and GTK version may appear **only in the separately reviewed issue snapshot**, not continuously in records. Saturate counters, cap distinct `(day, component, event, result)` keys, and drop unknown events.

When enabled, persist only these aggregates under `$XDG_STATE_HOME/groundhog/diagnostics/` (0700), with 0600 files, no symlinks, atomic replacement, and at most **three 256-KiB daily files** covering no more than seven days. No file is created before opt-in. Disable immediately stops collection and deletes all files; failure to delete is shown in Preferences and prevents a false “cleared” confirmation. Disk or permission failures disable disk persistence for the session, retain at most 64 KiB of the same sanitized aggregates in memory, and show “Diagnostics could not be saved”; messaging continues. Named instances use their already isolated XDG state directory. A crash leaves only prior completed aggregates; there is no crash dump or reporter. Other same-UID processes may read these files, so the UI must not promise stronger protection than the charter’s A4 boundary.

`GhIssueDialog` gains structured, user-editable **Steps to Reproduce**, **Expected Result**, **Actual Result**, labels and related commit IDs, backed by a reusable nostr-gtk issue-fields widget/data shape. Optional attachment URLs are manual text references only; Groundhog does not upload files. Related commits go into the issue body as a `## Related commits` section of Git object IDs (any length the repository's object format uses), exactly as Gnostr's bug-report assembly does — **not** as `e` tags, which NIP-34 reserves for Nostr events. Labels use the existing `nip34_create_issue()` label parameter (`nips/nip34/include/nip34.h:220-245`), so no NIP-34 builder change is required. Gnostr may continue using its Blossom integration through an injected attachment service, but it is not a Groundhog default.

An “Include Local Diagnostics” checkbox is **off for every new issue**, even when collection is on. Checking it snapshots at most **8,000 UTF-8 bytes** of the allowlisted aggregate report; the UI displays the exact appendix and its data-class explanation. The issue draft is canonicalized and frozen at review, with total body ≤16,000 bytes and title ≤640 bytes. If too long, block Review and ask the user to shorten content or deselect diagnostics; do not trim. Review displays the exact final body, tags, normalized relay list, account pubkey and repository address. The existing public-warning dialog remains cancel-default. Only Publish signs and sends to those relays. Changing any field invalidates the reviewed snapshot; changing accounts closes/invalidates it. Close, unroot or cancellation stops pending signer and publisher work, while warning that an already sent EVENT cannot be recalled. Relay OK and partial/unconfirmed outcomes keep the existing honest wording; no automatic re-sign or retry creates a second issue.

Amend charter §0, P10, PD-10, §7.11 and the issue-report promise to say: “No diagnostics are collected by default; local sanitized aggregates can be enabled; an issue includes them only after an explicit preview and Publish.” Keep the ban on plaintext logs and network telemetry. Extend `tests/check_privacy.py` with a pinned GSettings key and a static allowlist of diagnostic field/event names; mutation fixtures must fail if a raw error string or identifier is added.

### 3.4 Localization and accessibility

Initialize locale and bind `groundhog` with UTF-8 **before constructing settings, tray labels or UI**. Extract strings from C, committed Blueprint/compiled UI, desktop entry and metainfo into one POT; install the eight catalogs in `locale/<lang>/LC_MESSAGES/groundhog.mo` for every package format. Keep Blueprint as the UI string source of truth. Use `ngettext` for counts; translate CLI descriptions, tray/menu labels, issue consent and diagnostic disclosures. Portuguese is `pt_BR`; Farsi is `fa`.

(When catalogs are added after alpha 6:) create draft catalogs from extraction, have native-language review of security/consent, relay, “public issue,” update and diagnostic copy, then run untranslated/fuzzy checks. Do not ship machine draft consent text as reviewed. Test Arabic/Farsi RTL with avatar menu, message alignment, send icon, tray direction, dialogs and mixed-direction Nostr IDs/URLs; wrap identifiers in directional isolation rather than reversing their bytes. Test Japanese line wrapping and IME send behavior; use locale-aware dates and plural forms. Replace fixed `xalign` values at the cited message/poll/new-message surfaces with direction-aware alignment. Ensure every new icon-only action has an accessible name and keyboard route; Orca must announce reaction chips, copied confirmation, avatar action, history-partial state, diagnostic opt-in and public-issue consequences without relying on color or emoji alone.

### 3.5 Contracts added after design review

**dbusmenu wire contract (`gn-status-notifier`).** Today `GetLayout`, `GetGroupProperties` and `GetProperty` ignore depth/property filters and invent properties for unknown IDs (`gnome/common/gn-status-notifier.c:45-176`). The new presenter: honours `GetLayout(parentId, recursionDepth, propertyNames)` and `GetGroupProperties(ids, propertyNames)` filtering; uses `type="separator"`, `toggle-type="checkmark"` and **integer** `toggle-state` (0/1); returns `org.freedesktop.DBus.Error.InvalidArgs` for unknown IDs in every method and lists them in `EventGroup`'s error array; bumps `menu_revision` and emits `LayoutUpdated(revision, 0)` **after** swapping in the new immutable snapshot. `Event` carries no revision, so a click is validated against the current snapshot only (IDs are stable per item; a removed item's ID is never reused). Tests use a fake watcher/host that re-queries `GetLayout` after `LayoutUpdated`.

**Launch-on-login / background state machine (`gh-background`).** Two independent settings: `run-in-background` (existing) and `launch-on-login` (new). Getters/setters: `gh_background_get/set_enabled_async()` (existing, `gh-background.c:779-808`) and new `gh_background_get/set_launch_on_login_async()`. One serialized reconciler owns the host autostart file and the portal; each request carries a sequence number and late completions with an older number are ignored. Rules: launch-on-login requires background, so enabling launch enables background (with the existing disclosure); disabling background turns launch off too; disabling launch removes autostart only. Portal grants background but denies autostart → launch reverts to off, background stays on; portal denies background → both off (today's behaviour, `gh-background.c:299-329`). A host autostart file the user disabled (`X-GNOME-Autostart-enabled=false`) is reported as “off (disabled in system settings)” and not overwritten. Migration: an existing explicit `run-in-background=true` user value sets `launch-on-login=true` once, preserving today's autostart behaviour.

**NIP-29 history seam.** First prove fetch vs listing (A1); the schema change below is applied only if the defect is in fetching or paging. The live subscription stays as is. Historical paging uses a **separate per-group history scope** (own REQ: chat kinds, `#h`, `until = oldest_known − 0`, `limit 500`) created on demand by Earlier Messages or first join, keyed by the group identity that already includes the relay URL (`gh-nip29-service.h:18-41,92-97`). Persisted per group, in one transaction with the page's admitted events: `oldest_until`, `history_state ∈ {incomplete, complete, partial}`. Page outcomes: events + EOSE → advance `oldest_until` to the oldest admitted `created_at` (and keep fetching while under the 16-page session cap); EOSE with zero events → `complete`; failure/offline/cancel → no position change; all events at one timestamp filling the page → `partial` (“Some earlier messages may be unavailable”). After the cap, the next Earlier Messages resumes from `oldest_until`, never from the newest page. `GhRelayScope` paging (`gh-relay-scope.h:58-90,181-192`) is reused for the history scope only.

**nostr-gtk split ownership.** `gn_content_parser` (an OBJECT library currently embedded in `nostr_gtk`, `nostr-gtk/CMakeLists.txt:113-180`) moves into a new installed library **`nostr_gtk_portable`** that owns every portable public symbol (content parser, Markdown, references, OG card, media viewer, issue fields); `nostr_gtk` links it PUBLIC and keeps its existing symbols, so legacy consumers and the GIR keep working; pkg-config `nostr-gtk-portable-1.0` and a CMake export are added; Meson (`nostr-gtk/meson.build:89-105`) gets the same split. Portable APIs must build at nostr-gtk's floor **GTK 4.6 / libadwaita 1.2** (`nostr-gtk/CMakeLists.txt:40-43`), not Groundhog's 4.14/1.5.

**Issue preview = published event.** One canonical builder produces the unsigned issue event (assembled body including optional sections and diagnostics appendix, tags) and is used for both the Review preview and Publish; editing any field or toggling diagnostics invalidates it. Length checks apply to the **assembled** UTF-8 body. The dialog's existing generation/cancel/partial-OK handling (`gh-issue-dialog.c:35-104,218-241`) is preserved.

**OG artwork.** `GhWebContent` already fetches consent-gated HTML and extracts title/description but discards `og:image` (`gh-web-content.c:58-100`). Alpha 6 ports the presentation card; artwork is an **additional explicit action** on the card (“Load image”), so `GhWebResult` gains an inert image URL that is never fetched automatically.

**Markdown is a new implementation.** Gnostr's `markdown_pango.c` converts straight to Pango (`apps/gnostr/src/util/markdown_pango.c:87,259,379`); the bounded token parser is new code, with compatibility fixtures proving the Gnostr wrapper's output is unchanged. `GhMessage` bodies are immutable (`gh-message.h:30-51`), so the render cache is keyed by account + message id + display-name generation only (no body-revision field).

**Async ownership.** Every async path has one owner on the main context and a generation: row → worker parse (owner: conversation view cache; result applied only if the row's bind generation matches); card/viewer → load (owner: conversation view; cancelled on unbind, account switch, dialog close); tray → actions (owner: `GhTray`); diagnostics write (owner: `GhDiagnostics`; disable cancels pending writes and deletes after they settle, so a late write cannot recreate files); issue publish (existing dialog generation). Tests cover late callbacks after unbind/switch/disposal.

**Performance gate.** Markdown and reference rendering are measured with Groundhog's own conversation-open probe (`GROUNDHOG_TEST_TIMING=1`, `tests/ui/test_conversation_view.c`; baseline `prompt-exports/optimize-groundhog-conversation-open-runs.md`): 1,000-message first open and A→B→A re-open with real Markdown bodies, long bodies and cold/warm cache must stay within 10% of the alpha-5 p50 (240/250 ms), measured before first paint.

**Versions.** nostr-gtk gains public API → **1.1.0** (MINOR); NIP-34 unchanged (no builder change); Groundhog stays **0.12.0** (alpha 6). Update `VERSION_MANIFEST.md` and CMake/Meson versions together in B1.

### 3.6 Sliding message window (owner request 2026-10-09)

**Current state.** Conversations open with the newest stored page (`GH_STORE_CONVERSATIONS_PAGE_SIZE 50`, `gnome/groundhog/src/store/gh-store-conversations.h:63`; NIP-29 and MLS likewise, `gh-store-nip29.h:90`, `gh-store-mls.h:43`) and Earlier Messages prepends further 50-message pages, but **nothing is ever unloaded**: the in-memory `GhConversation` (`src/app/gh-conversation.c:13-20,89-138`) keeps every paged-in and live message, so the model — and with it GTK’s retained row range (~200 rows once the model is that large, measured in `prompt-exports/optimize-groundhog-conversation-open-runs.md`) — grows for the life of the session.

**Design.** Make the conversation model a bounded window over the store:
- **Open:** load the newest **30** messages (≈ two screens), not 50.
- **Scroll up:** near the top, page in **25** older messages from the store (then the network, per §3.5 history seam).
- **Bound:** keep at most **120** messages in memory per open conversation. When the window exceeds it, drop the end farthest from the viewport (oldest when reading recent, newest when reading old history) in whole pages; dropped messages stay in the encrypted store.
- **Scroll down after reading history:** page newer messages back in from the store; a **Jump to latest** button appears whenever newer messages are unloaded, and live messages arriving then increment its badge instead of growing the model.
- **Inactive conversations** shrink back to the newest 30 when the user switches away.
Anchoring keeps the visible row fixed across prepend/append/trim (same mechanism as the alpha-5 “Earlier messages” fix). Reactions, poll tallies, reply previews and unread markers must resolve against the store, not only the in-memory window (reply target outside the window → “jump to message” loads the page around it). Constants live in one header so tests can shrink them.

**Expected effect and gate.** The model never exceeds 120 items, so GTK never builds more than ~120 rows; first open drops from 205 bound rows to ≤30–40. Gate with the conversation-open probe: 1,000-message first open and A→B→A re-open p50 must improve on alpha 5 (240/250 ms), plus a long-scroll test (scroll to the oldest of 1,000 and back) asserting the model size bound, anchoring within 1 px and no lost/duplicated messages.

## 5. Risks and migration

- **Store migration:** the next encrypted-store schema migration adds NIP-29 history position/partial columns or table. It must be atomic and one-way under the existing “newer schema” refusal rule. An older Groundhog cannot reopen the migrated store; document this in release notes. If history metadata is absent after migration, initialize it as *incomplete* from the earliest known stored message, never as fully fetched.
- **NIP-34 publication:** an inline diagnostic appendix is public, attributable and effectively irreversible. A relay may accept an EVENT without returning OK; keep the existing “may have reached a relay” outcome. Never rebuild/re-sign automatically.
- **Same-UID privacy:** local diagnostics contain only allowlisted aggregates, but other applications running as the same user can read the files. No claim of protection against A4 is made.
- **Library ABI:** splitting portable symbols out of `nostr_gtk` can break static/shared consumers if symbol export or pkg-config transitivity changes. Keep old public signatures and validate installed-library linkage, GIR generation and a standalone consumer.
- **History completeness:** NIP-01 timestamp-filter paging cannot prove complete traversal of an arbitrarily dense same-second boundary on every relay. Surface a partial result rather than silently skipping events.
- **Packaging unknowns:** exact package manifest paths and installed md/locale integration are not in the provided selection. The inventory step must locate all five channels before implementation proceeds; this is validation of file locations, not an unresolved behavior decision.
