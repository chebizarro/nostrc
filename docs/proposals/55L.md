# NIP-55L

## Linux/Desktop Signer Application over D-Bus

`draft` `optional`

This NIP describes how a desktop Nostr client asks a separate signer
application for signatures, encryption and decryption over the D-Bus
**session bus**. It plays the role [NIP-55](55.md) plays on Android: the
secret key stays in the signer, and the user approves each client.

This text describes protocol revision **nip55l 0.7.0**. The reference
implementation is `nips/nip55l` (library, `nostr-signer-daemon`, and the
introspection XML `nips/nip55l/dbus/org.nostr.Signer.xml`). The signer that
ships is Grotto (`apps/grotto`, daemon `grotto-daemon`). Grotto exports the
same `nip55l` service code. Clients that use it today are Groundhog
(`gnome/groundhog/src/identity/gh-signer-nip55l.c`) and gnostr. The test
`nips/nip55l/tests/test_signer_dbus_contract.c` checks the method surface.

### Activation

A signer SHOULD install a D-Bus service file so the first call starts it:

```ini
[D-BUS Service]
Name=org.nostr.Signer
Exec=/usr/bin/grotto-daemon
SystemdService=grotto-daemon.service
```

The reference daemon installs the same file with
`Exec=.../nostr-signer-daemon`. At most one implementation can own the name
at a time. Flatpak builds install `org.nostr.Signer.service` from their own
manifest.

The approval UI is a separate process. Grotto's UI is `org.nostr.Grotto`,
and it is D-Bus activatable (`grotto --gapplication-service`). The daemon
starts the UI with `org.freedesktop.DBus.StartServiceByName` when a request
needs an answer and no UI is on the bus.

## Conventions

* Every argument is a D-Bus string (`s`) unless stated otherwise. D-Bus
  strings must be valid UTF-8.
* `identity` (the *identity selector*) chooses the key:
  * `""`: the signer's active identity.
  * `npub1...` or a 64-hex x-only public key: exactly that identity, one
    of those `ListIdentities` returns. If the signer holds no key with that
    public key, the call fails with `Error.NoKeyConfigured` before any
    prompt. If it cannot read its key store to find out, the call fails
    with `Error.Internal`, also before any prompt. The signer never falls
    back to a different key.
  * Any other string is a signer-local key id or label. It must match exactly
    one stored item; an unknown or ambiguous id or label fails with
    `Error.NoKeyConfigured`, never selecting the active, first stored, or
    environment key. An unreadable key store instead fails with `Error.Internal`.
  * An `nsec1...` string is refused with `Error.InvalidInput`. A 64-hex
    selector is always read as a **public** key and never as key material,
    including when an in-process caller bypasses D-Bus normalization. Secret
    keys enter through `StoreKey` or the signer environment, not selectors.
* `pubKey` / `peerPubKey`: the counterparty as 64-hex x-only. Other forms
  are rejected with `Error.InvalidInput`.
* `app_id`: an optional, **unverified** label. See
  [App identification](#app-identification).
* NIP-04 and NIP-44 ciphertexts use the encodings defined by those NIPs
  (NIP-44 v2 payloads are base64).

## Methods

"Gated" means the call goes through the approval model in
[Approval and consent](#approval-and-consent). Each gated method has a
`...ForApp` variant (since 0.4.0) that takes an extra trailing
`app_id` argument. The reply is the same.

### Client methods

| Method | In | Out | Gated (kind) |
|---|---|---|---|
| `EnableTypedApprovalErrors` (0.5.0) | - | - | no |
| `GetPublicKey` | - | `npub` | yes (`get_public_key`) |
| `GetPublicKeyForApp` | `app_id` | `npub` | yes |
| `ListIdentities` (0.6.0) | - | `as npubs` | no |
| `SignEvent` | `eventJson`, `identity`, `app_id` | `signed_event` | yes (`event`) |
| `NIP04Encrypt` | `plaintext`, `pubKey`, `identity` | `encryptedText` | yes (`nip04_encrypt`) |
| `NIP04Decrypt` | `encryptedText`, `pubKey`, `identity` | `plaintext` | yes (`nip04_decrypt`) |
| `NIP44Encrypt` | `plaintext`, `pubKey`, `identity` | `encryptedText` | yes (`nip44_encrypt`) |
| `NIP44Decrypt` | `encryptedText`, `pubKey`, `identity` | `plaintext` | yes (`nip44_decrypt`) |
| `NIP44EncryptB64` | `plaintextB64`, `pubKey`, `identity` | `encryptedText` | yes (`nip44_encrypt`) |
| `NIP44DecryptB64` | `encryptedText`, `pubKey`, `identity` | `plaintextB64` | yes (`nip44_decrypt`) |
| `NIP44DeriveConversationKey` (0.3.0) | `peerPubKey`, `identity`, `app_id` | `conversationKey` | yes (`nip44_conversation_key`) |
| `DecryptZapEvent` | `eventJson`, `identity` | `decryptedEvent` | yes (`zap_decrypt`) |
| `GetRelays` | - | `relaysJson` | yes (`get_relays`) |

Each `...ForApp` variant (`NIP04EncryptForApp`, `NIP44DecryptB64ForApp`,
`DecryptZapEventForApp`, `GetRelaysForApp`, and so on) appends `app_id` as
its last input. `SignEvent` and `NIP44DeriveConversationKey` already take
`app_id`, so they have no `ForApp` variant.

#### GetPublicKey

Returns the active identity as a bech32 `npub`. If no key is configured, it
fails with `Error.NoKeyConfigured`. If the key store cannot be read, it
fails with `Error.Internal`.

#### ListIdentities

Returns the npubs of every identity the signer holds, with no secrets: its
stored identities and, if the signer was started with a key in its
environment, that key (the reference daemon's `NOSTR_SIGNER_SECKEY_HEX` or
`NOSTR_SIGNER_NSEC`, which is then its active identity). Each npub appears
once. Every npub in the list is a valid selector, and an npub or hex selector
for a key not in the list fails with `NoKeyConfigured`. It is not gated. A
client uses it to pick a selector or to check that the signer holds a key.

If the signer cannot read its key store, it fails with `Error.Internal`
rather than return a partial or empty list. A signer with no key store at
all (no Secret Service on the bus, or none built in) lists its environment
key alone, and fails with `Error.Internal` if it has none. An empty array
therefore means the signer holds no identity. Before 0.7.0 the reference
daemon answered an empty array in these cases and left the environment key
out. Signers older than 0.6.0 answer `UnknownMethod`.

#### SignEvent

`eventJson` is an unsigned event. The reply is the **complete signed event
JSON** (`id`, `pubkey`, `created_at`, `kind`, `tags`, `content`, `sig`).
`pubkey` is always set to the signing key, whatever the input said. If
`created_at` is missing or 0, the signer fills in the current time. Signers
before 0.2.0 returned only the 128-hex signature. Clients MUST parse the
returned event. Clients SHOULD check `pubkey` against the identity they
expected. Errors: `InvalidInput` (not an event), `Internal`, plus the
gating errors.

#### NIP44EncryptB64 / NIP44DecryptB64

These carry a binary-safe NIP-44 plaintext as standard base64, because raw
binary cannot be sent as a D-Bus string. The ciphertext is an ordinary NIP-44
v2 payload. They are separate method names, not a flag, so an older signer
answers `UnknownMethod` instead of encrypting the base64 text as if it were
the plaintext.

#### NIP44DeriveConversationKey

Returns the NIP-44 v2 conversation key between `identity` and `peerPubKey`
(HKDF-extract(SHA-256, ECDH shared x, salt `"nip44-v2"`)) as 64 lowercase
hex. The returned key opens every NIP-44 payload exchanged with that peer,
so the call is gated like `SignEvent`. The prompt preview is the peer.

#### GetRelays

Returns a JSON array of the user's explicitly configured relay URLs. They
come from `$XDG_CONFIG_HOME/nostr/relays.conf`, or else from the relays set
in the signer's UI. They are never fetched from the network. If nothing is
configured it returns `Error.NotFound`, and the client uses its own relays.
A malformed `relays.conf` returns `Error.InvalidConfig`.

### Approval-UI and management methods

Only the signer's own installed approval UI may call these methods. The
signer recognises it by executable path and device/inode, or by its Flatpak
app id. Any other caller gets `Error.PermissionDenied`. Clients MUST NOT
depend on them. They are listed so that a signer and its UI can be built
separately.

| Method | In | Out |
|---|---|---|
| `ApproveRequest` | `request_id`, `b decision`, `b remember`, `t ttl_seconds` | `b ok` |
| `GetApprovalInfo` (0.4.0) | `request_id` | `a{sv} info` |
| `ListPendingRequests` (0.7.0) | - | `a(sssss) requests` (`app_id, identity, kind, preview, request_id`) |
| `ListGrants` | - | `a(sssbt) grants` (`kind, principal, identity, allow, expires_at`) |
| `RevokeGrant` | `kind`, `principal`, `identity` | `b removed` |
| `StoreKey` | `key`, `identity` | `b ok`, `npub` |
| `ClearKey` | `identity` | `b ok` |
| `CreateProfile` (0.6.0) | `display_name`, `passphrase`, `recovery_hint`, `label`, `b use_hardware_key` | `b ok`, `npub` |

`GetApprovalInfo` has these keys: `request_id`, `kind`, `principal`,
`principal_kind` (`flatpak`, `snap`, `systemd-scope`, `executable`,
`website` or `unidentified`), `app_id`, `exe`, `via`, `claimed_app_id`,
`identity`, `preview` (strings), `attested` and `rememberable` (booleans),
and `calls` (u).

`StoreKey`, `ClearKey` and `CreateProfile` are restricted to the identified
trusted approval UI. Other callers need the daemon's explicit tests/scripts
override `NOSTR_SIGNER_ALLOW_KEY_MUTATIONS=1`; it is not required for the
trusted UI. In `CreateProfile`, `passphrase`,
`recovery_hint`, `label` and `use_hardware_key` are reserved: pass `""` for
the strings and `false` for the boolean.

### Signals

| Signal | Args |
|---|---|
| `ApprovalRequested` | `app_id` (the attested principal), `identity` (resolved npub), `kind`, `preview`, `request_id` |
| `ApprovalCompleted` | `request_id`, `b decision` |

These signals are for the approval UI. A client gets its own result as the
method reply.

## Errors

| Name (`org.nostr.Signer.Error.*`) | Meaning |
|---|---|
| `ApprovalDenied` | The request was not approved. See typed errors below. |
| `ApprovalTimedOut` | (opt-in) A parked request expired with no answer. |
| `NoApprovalAgent` | (opt-in) A prompt was needed but no approval UI could be reached. |
| `IdentityChanged` | (opt-in) The request was approved, but the selector no longer resolves to the approved npub. |
| `RateLimited` | Too many requests, or too many are waiting for approval. |
| `NoKeyConfigured` | The selector resolves to no identity the signer holds. |
| `InvalidInput` | Bad event, peer key or selector (for example an nsec). |
| `PermissionDenied` | The caller may not use a UI or management method. |
| `NotFound` | `GetRelays`: no relays are configured. |
| `InvalidConfig` | `GetRelays`: `relays.conf` is malformed. |
| `Internal` | Signer or backend failure, for example a key store that cannot be read (`ListIdentities`, or a selector the signer cannot resolve because of it). |

Error messages are informational only. They are not part of the contract.

### Typed approval errors (0.5.0)

By default, a timeout, a missing approval UI and an identity change all
return `ApprovalDenied`. If a connection calls `EnableTypedApprovalErrors`,
it gets `ApprovalTimedOut`, `NoApprovalAgent` and `IdentityChanged` for
those cases for as long as it stays connected. After that, `ApprovalDenied`
means only a real denial: by the user, by a remembered decision, or because
the caller disconnected. The opt-in only changes that connection's own
replies.

A connection's calls are handled in order. So a client MAY send
`EnableTypedApprovalErrors` without waiting for the reply, just before its
first gated call. Groundhog does this. A pre-0.5.0 signer answers
`UnknownMethod`, and the client can ignore it.

## Approval and consent

Every gated call is checked in this order:

1. **Principal.** The signer works out who the caller is from the bus
   connection, **never from an argument**. It uses the Flatpak app id, Snap
   name, systemd app scope plus executable, or else the executable. A caller
   the bus cannot attest is *unidentified*.
2. **Identity.** The selector is resolved to one canonical npub.
3. **Permission.** A single evaluator checks `(principal, pinned npub,
   operation, optional event kind)` in `signer-permissions-v2.ini`.
   Explicit deny → required-confirmation policy → explicit scoped allow → live
   client tier/headless default → prompt. Event scopes are exact-kind by default;
   non-event operations have no event kind. Expiry is absolute and never renewed
   by activity. Unknown clients default to Low trust. Built-in headless defaults
   still match executable path and inode, only for unsandboxed same-user callers;
   they enter this evaluator, never bypass explicit denial.
4. **Prompt.** If nothing decided the call, it is parked and
   `ApprovalRequested` is emitted. The approval UI shows the request and
   answers with `ApproveRequest`. If `remember` is true, the decision is
   stored for `ttl_seconds`, or forever if that is 0. Since 0.7.0, an event
   decision remembers **only its validated event kind**, not every event.
   Required-confirmation kinds still prompt despite remembered allows; remembered
   denials remain effective. Persistence failure does not confirm remembered
   access. A decision is not remembered for an unidentified caller. A parked request expires after
   **300 s** (or an earlier authenticated transport deadline). Only identical
   principal + pinned identity + operation + canonical-argument digest calls
   share a request. Different payloads or peers do not inherit that decision;
   disconnect/cancel removes only that continuation. Request IDs are opaque
   CSPRNG values. D-Bus and NIP-5F use the same GTK-free daemon-owned
   `SignerApprovalService`; its internal NIP-46 caller is `nip46:<lowercase
   authenticated-client-hex>`, identified/rememberable but never an approver.
   NIP-46 adapter/pairing is delivered separately (G05/G06), not by this API.

Request kinds: `event`, `nip44_conversation_key`, `get_public_key`,
`get_relays`, `nip04_encrypt`, `nip04_decrypt`, `nip44_encrypt`,
`nip44_decrypt`, `zap_decrypt`.

Approval can take up to 300 s, so clients MUST use a D-Bus call timeout
longer than that. Groundhog uses 330 s. The default libdbus/GDBus timeout
of 25-30 s is too short.

**Identity binding.** An approved request runs only if its selector still
resolves to the npub shown in `ApprovalRequested`. Once an identity is
resolved, execution uses that npub rather than re-resolving a mutable label
or active selector; this also applies to grants that need no prompt. If the
bound identity is no longer available when approval arrives, the call fails
with `IdentityChanged`, or `ApprovalDenied` if the client did not opt in.
Changing the active account does not redirect the call: it may still use the
original identity if that key remains available. If the key store becomes
unreadable while the prompt is open, the call
fails with `Internal` for every client, not an approval error. NIP-04 and NIP-44 replies carry no pubkey, so clients depend on this
guarantee for them.

### Scoped permission storage and migration (0.7.0)

`$XDG_CONFIG_HOME/gnostr/signer-permissions-v2.ini` has `[permissions] version=2`
and SHA-256 encoded `record-…` section ids over length-delimited scope fields,
never raw principals in section names. Each record has `principal`, `identity`,
`operation`, `event-kind` (-1 for operation-wide), `decision` (allow/deny/review),
`expires-at` (absolute Unix seconds, 0 forever). Review records also have
`created-at` and `legacy-scope`; they are **Needs review**, never executable,
and are pruned after 90 days. A missing directory is created with mode 0700;
existing shared `gnostr` directory permissions are not changed. Atomic durable
file replacement uses 0600, and the shared profile guard refuses the owner's
profile under test. Unknown versions or a syntactically unreadable v2 file
fail closed. A semantically invalid record is quarantined in place: no allow
authority, deny its recoverable scope only, omit it from lists, and log a fixed
message without record contents. Unrelated records remain usable; clear/replace
can repair a quarantined scope.

Legacy `signer-grants.ini` is imported **once**, then retained only for
sanitation on **every load**. The initial import preserves valid non-event
permissions (including identity-wildcard allows) with their original absolute
expiry; forever stays forever. Operation-wide event denies are preserved and
broad event allows become non-executable Needs review. `[permissions]`
`legacy-imported=true, legacy-complete=false` is durably saved before removing
broad event allows from the legacy file; sanitation must succeed before the
initial evaluation is enabled. Completion sets `legacy-complete=true`. Restart
after a partial migration retries sanitation, not import. Any existing v2 file,
including a pre-marker file, is authoritative. Later legacy writes cannot add,
widen, deny or resurrect v2 permissions; broad event allows are stripped but do
not create new review rows. A corrupt legacy file is ignored with a fixed log
message and rewritten empty. Later sanitation failure does not disable v2.
New identity-wildcard allows are supported only for `get_relays`. Migrated
wildcard non-event allows carry `legacy-scope=identity-wildcard non-event allow`;
a replacement may retain that scope only without changing its expiry. Legacy
wildcard denies are retained to avoid weakening a prohibition.
No global bunker auto-approve setting or remote allowlist is signing authority.
Pairing/client admission inventory is G04/G06 work, not imported signing grants.
Older binaries cannot consume v2 scopes; rollback never restores broad event
allows. New non-event writes are v2-only (older binaries may ask again).

`ListGrants` keeps its signature but lists **only operation-wide allow/deny
rows**, not exact-kind rows, review markers, tiers or built-in defaults.
`RevokeGrant("event", principal, identity)` clears every event scope for that
pair (including review and operation-wide deny); other operations clear their
operation-wide row. Revocation cancels only pending/queued work covered by that
principal, identity and operation (all event kinds for `event`).
Tier-derived access remains until the tier is lowered. `ListPermissions` and
`SetPermissions` D-Bus dispatch are G04's Control1 surface; G03 provides the
C list/replace-with-expected-revision/needs-review/clear API. Stale replacement
revisions fail with Conflict. Automatic queued admission checks the permission
revision and absolute-expiry fence before identity/key use; a changed policy is
rechecked on the owner thread and re-admitted if still allowed, without duplicate
cryptography. Explicitly approved queued requests survive unrelated permission
changes (including another completed remembered approval). A covering deny or
revocation invalidates queued work before key use.

Low/Medium/Full tiers are evaluated live through a per-client lookup, not
expanded into grant rows. Low permits get_public_key after first consent;
Medium adds get_relays/ping and the named public-publishing set; Full permits
admitted known operations/custom event kinds except required-confirmation,
conversation-key/raw-key export and pairing admission. Neither tiers nor
first-party defaults authorise conversation-key export: it requires an explicit
allow (including a valid migrated allow). Pairing always requires admission and
cannot inherit a cached allow. Explicit allows can otherwise extend a tier;
explicit denies always win, even for unknown operations or invalid/absent kinds. The adapter must enforce its client's
method allowlist/transport admission before evaluation. Policy data lives in
`nips/nip55l/src/glib/signer_permission_policy.h`: consent policy belongs in the
signer, while kind constants come from `libnostr/include/nostr-kinds.h`. The
§5.4 proposed sets are data, not evaluator logic; exact membership still needs
owner sign-off before G07. The required-confirmation list is injectable for G04
Settings; client-store persistence and tier UI are deferred to G04/G07.

### Context and request snapshots (0.7.0, additive)

`ApproveFlowRequest(request_id:s, encrypt:b, seals:b, ttl_seconds:t) → ok:b`
is an approver-only room-send decision. Explicitly chosen encryption uses a normal
scoped expiring permission; required seal signing uses daemon-memory-only consent
bound to principal, identity, transport, exact operation/kind and flow ID, for at
most `flow_size` distinct requests and 600 seconds. Expired, exhausted, mismatched
or restarted flows ask again; explicit denies win. Ordinary remembered allows do
not bypass required-confirmation kinds. See [the full contract](../dbus-interface.md#approveflowrequest).


`CallWithContext(method:s, arguments:v, context:a{sv}) → reply:v` wraps the
exact input and output **tuples** of `SignEvent`,
`NIP44DeriveConversationKey`, `NIP04Encrypt`, `NIP04Decrypt`, `NIP44Encrypt`
and `NIP44Decrypt`. It uses the same principal, validation, gate and backend
as direct calls; the daemon never calls its own D-Bus methods.

`GetPublicKey`/`GetRelays` stay direct-only because D-Bus cannot encode
an empty input tuple inside a variant; no invented sentinel or encoding is
accepted. `*ForApp`, `*B64`, `DecryptZapEvent`, `EnableTypedApprovalErrors`, management
methods, recursion and unknown names are deliberately direct-only. The
wrapper rejects them, wrong tuple signatures, duplicate/unknown context keys
and wrong value types with `Error.InvalidInput`. Typed-error opt-in on the
connection applies equally to wrapped calls. Context permits `reason:s`
(≤160 Unicode characters **and** ≤512 UTF-8 bytes), `purpose:s` and
`flow_id:s` (≤64 UTF-8 bytes each), plus optional `flow_size:u` (1..1024,
nonempty flow ID required; includes the sender's own destination copy).
Context is unverified presentation and
grouping data, never identity, permission or admission authority.

`GetApprovalInfo` keeps its existing fields and signature. Added fields:
`transport:s`, `operation:s`, optional validated `event_kind:u` (absent is
not kind 0), `event_summary:a{sv}` (type, bounded safe preview, tag count or
peer/operation details), `reason:s`, `reason_source:s` (`caller` or `signer`),
`flow_id:s`, `expires_at:t` (Unix seconds), `remaining_seconds:u` (monotonic
snapshot) and `state:s`. Summaries exclude keys, tokens, ciphertext and
private message bodies. Unknown fields are safe for old UIs to ignore.
`ApprovalCompleted(sb)` is unchanged and is not proof of valid cryptography.

Internally the service exposes session pause/generation and cancel hooks.
Pause cancels queued requests and suppresses in-flight results not handed to
the transport, including keyring-unlock results after pause/resume. New
failures are `Error.Paused` and `Error.Cancelled`; direct internal/socket
adapters receive typed failures; existing NIP-5F wire approval failures retain
`ApprovalDenied`. Legacy D-Bus cancellation remains
`ApprovalDenied` unless the connection enabled typed errors. No `SetPaused`
D-Bus method is introduced here (G04 owns Control1).

### Built-in first-party headless grants

These defaults are retained through the shared service and are evaluated
only for verified same-user EXE/SYSTEMD_SCOPE callers with matching installed
path **and** device/inode. Explicit denies override them (and matching
allows); no sandbox, web-origin or NIP-46 caller inherits them. Build-time
`NIP55L_DEFAULT_GRANTS` can change the list; stock membership is:

| Executable | Implicit operations |
|---|---|
| `<bindir>/nostr-homectl` | `get_public_key`, `get_relays`, `nip44_decrypt` |
| `<bindir>/nostrfs`, `nostr-home-fuse`, `nostr-home-syncd`, `nostr-home-fetch`, `nostr-homed-provision`, `nostr-home-status` | `get_public_key`, `get_relays` |
| `<libexecdir>/nostr-notify-daemon` | `get_public_key`, `get_relays` |
| `nostr-seal` and all other executables | None; explicit grants or consent required |

There are no implicit event-signing, NIP-04, encrypt or conversation-key
export grants. G03 extends policy to per-kind scopes/migration; that work is
not silently implemented by this extraction.

## App identification

The signer identifies the calling app from its D-Bus connection. The
`app_id` argument is **not** trusted:

* From most callers it is only a label. The prompt shows it as "claims to
  be ...", and it is reported as `claimed_app_id`.
* If the caller is the installed browser bridge
  (`nostr-signer-webext-host`), an `app_id` that is a web origin becomes a
  sub-principal. Grants are then kept per website, and `via` names the
  bridge.

## Capability discovery and versioning

There is no version method. Clients detect features by trying them. A method
that is missing returns `org.freedesktop.DBus.Error.UnknownMethod`. A client
can also read the interface with `org.freedesktop.DBus.Introspectable`.
Every change since 0.2.0 has added methods and left existing ones alone,
except as noted below:

| Rev | Change |
|---|---|
| 0.2.0 | `SignEvent` returns the full signed event instead of only `sig`. |
| 0.3.0 | `NIP44DeriveConversationKey`. |
| 0.4.0 | Access control. `GetApprovalInfo` and the `...ForApp` variants. |
| 0.5.0 | `EnableTypedApprovalErrors`, `ApprovalTimedOut`, `NoApprovalAgent` and `IdentityChanged`. |
| 0.6.0 | `ListIdentities` and `CreateProfile`. |
| 0.7.0 | Additive approver-only `ApproveFlowRequest` with bounded, ephemeral exact-scope room-send consent (ordinary grants never bypass required-confirmation); `flow_size` context metadata. Additive `CallWithContext` and structured `GetApprovalInfo` metadata; shared cancellable authorisation service, exact-argument joining and opaque IDs. Scoped per-event-kind permissions, absolute expiry, live trust-tier policy, required-confirmation enforcement, restart-idempotent unsafe legacy allow migration to Needs review, operation-wide-only `ListGrants` and all-event-scopes `RevokeGrant`. `ListPendingRequests`. The daemon starts the UI. `StoreKey`/`ClearKey` limited to the signer UI. `ListIdentities` also lists the environment key and fails with `Internal` when the key store cannot be read (it answered an empty array). Identity selectors and `GetPublicKey` fail with `Internal` instead of `NoKeyConfigured` when the key store cannot be read. Unknown or ambiguous key ids and labels fail with `NoKeyConfigured` instead of selecting another key; resolved calls are pinned to an npub even on auto-grants. A store failure during approval recheck fails with `Internal` instead of `IdentityChanged`/`ApprovalDenied`. |

`ListGrants`/`RevokeGrant` and `NIP44EncryptB64`/`NIP44DecryptB64` were
added later as additive methods without a revision number. Clients MUST
check for them by calling them.

## Sandboxing

Flatpak clients:

```json
"finish-args": [ "--talk-name=org.nostr.Signer" ]
```

Snap clients use a session-bus `dbus` plug for `org.nostr.Signer`. Sandboxed
callers are identified by their Flatpak or Snap id. Built-in default grants
never apply to them.

## Security considerations

* Client applications never receive the private key. Grotto's explicit
  key-management UI may transiently handle keys for create/import/export.
  `StoreKey`, `ClearKey` and `CreateProfile` require the existing trusted
  approver identification (path and inode or attested Flatpak identity);
  unattested callers are refused. `NOSTR_SIGNER_ALLOW_KEY_MUTATIONS=1` is an
  explicit tests/scripts override, not a prerequisite for the trusted UI.
* Any process of the same user can reach the session bus. Consent
  therefore depends on the signer identifying the caller from the bus. That
  identification is only as strong as the sandbox: an unsandboxed process
  can run another executable. This is why unidentified callers cannot have
  decisions remembered for them.
* `NIP44DeriveConversationKey` and the decrypt methods reveal message
  contents. They are gated per kind and per identity.
* Rate limits: a caller can open a new prompt at most once every 100 ms, and
  there are per-caller and global limits on parked requests. Management
  methods are limited to one call every 500 ms per sender.
* Clients SHOULD check that `pubkey` in a `SignEvent` reply is the identity
  they expected.

## Differences from NIP-55 (Android)

* The transport is synchronous D-Bus method calls. NIP-55 uses Intents and
  ContentResolver queries, and has no `nostrsigner:` URI scheme here.
* The calling app is identified by the system (from the bus connection),
  not by a `package` field the app supplies. There is no separate
  `get_public_key` handshake to register an app: the first gated call
  prompts the user.
* `SignEvent` returns the full signed event. There is no separate
  `signature`/`id` result.
* The interface adds methods NIP-55 does not have: identity selection
  (`identity`, `ListIdentities`), binary-safe NIP-44 (`*B64`), conversation
  key derivation, typed approval errors and `GetRelays`.
* There is no web-to-signer callback URL flow. Browsers go through the
  native-messaging bridge described in [App identification](#app-identification).

## Removed from earlier drafts

* `GetPublicKey` no longer takes or implies any `current_user`. The
  `current_user` argument was renamed `identity` and now follows the
  selector rules above.
* The ACL file `$HOME/.config/nostr-signer/acl.json` was never implemented.
  Grants live in `$XDG_CONFIG_HOME/gnostr/signer-grants.ini`, and only the
  signer manages them.
* The `SignEvent` output `signature` was replaced by `signed_event`.

## Example

```bash
dbus-send --session --print-reply --reply-timeout=330000 \
  --dest=org.nostr.Signer /org/nostr/signer org.nostr.Signer.SignEvent \
  string:'{"kind":1,"created_at":0,"tags":[],"content":"hello"}' \
  string:"" string:"org.example.App"
```
