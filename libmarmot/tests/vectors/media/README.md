## Regenerating `media-v2-mdk-v0.11.0.json`

The generator is a throwaway `#[cfg(test)]` module inside MDK's `marmot-app`
crate, so it calls MDK's own `pub(crate)` media code rather than a copy:
`derive_media_file_key`, `media_aad`, `canonical_media_type_v2`,
`MediaAttachmentReference::build_imeta_tag`, `parse_media_attachment`,
`encrypted_media_hash_matches`, the group image AAD, and the cgka-traits
`0x8002`/`0x8007` codecs and avatar URL normalizer (the `url` crate).

```sh
git clone https://github.com/marmot-protocol/mdk /tmp/mdk-v011
cd /tmp/mdk-v011 && git checkout 946e0547485c9a2c393c2048ec3a968fd50fb441
git apply /path/to/nostrc/libmarmot/tests/vectors/media/generator-mdk-v0.11.0.patch
cargo test -p marmot-app --lib media::w24_vectors -- --nocapture
# writes /tmp/w24-media-v2-vectors.json
```

Inputs are fixed: the media secrets are SHA-256 of ASCII labels and the nonces
are constants, so the output is deterministic.

`media_secret` is the already-exported `MLS-Exporter("marmot",
"encrypted-media", 32)` value.  The exporter step itself is libmarmot's
`mls_exporter()`, covered by the RFC 9420 key-schedule vectors; `test_media`
checks that encrypt/decrypt use that exporter with the `encrypted-media`
context and not the `group-event` one.

Negative cases carry MDK's verdict in `expect`, computed with MDK's receive
order (ciphertext hash, then AEAD, then plaintext hash):
`ciphertext_hash_mismatch`, `decrypt_failed`, `plaintext_hash_mismatch` or
`reject:<MediaAttachmentRejectionKind>`.

The `avatar_url.normalize` cases record what MDK's `url` crate produces.
libmarmot implements a strict subset of the WHATWG serializer and fails
closed outside it; `test_media` lists the inputs where it deliberately
rejects what MDK accepts (non-ASCII and punycode hosts).
