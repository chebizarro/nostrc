## Regenerating `media-v2-mdk-v0.11.0.json`

The generator is a throwaway `#[cfg(test)]` module inside MDK's `marmot-app`
crate, so it calls MDK's own `pub(crate)` media code rather than a copy:
`derive_media_file_key`, `media_aad`, `canonical_media_type_v2`,
`MediaAttachmentReference::build_imeta_tag`, `parse_media_attachment`,
`encrypted_media_hash_matches`, the group image AAD, and the cgka-traits
`0x8002`/`0x8007` codecs and avatar URL normalizer (the `url` crate).

```sh
git clone https://github.com/marmot-protocol/mdk /tmp/mdk-v011
cd /tmp/mdk-v011 && git checkout 946e0547485c9a2c393c2048ec3a968fd50fb441
git apply /path/to/nostrc/libmarmot/tests/vectors/media/generator-mdk-v0.11.0.patch
W24_KEY_SCHEDULE=/path/to/nostrc/libmarmot/tests/vectors/mdk/key-schedule.json \
  cargo test -p marmot-app --lib media::w24_vectors -- --nocapture
# writes /tmp/w24-media-v2-vectors.json
```

Inputs are fixed: the media secrets are SHA-256 of ASCII labels and the nonces
are constants, so the output is deterministic.

`media_secret` in `cases` is the already-exported `MLS-Exporter("marmot",
"encrypted-media", 32)` value.  The exporter step itself is pinned in
`exporter_step` (review N2): `exporter_secret` -> `media_secret` (and the
kind-445 `group_event_secret`), computed in the generator with openmls's own
crypto provider (`openmls_rust_crypto`: SHA-256, HKDF-Expand) and RFC 9420
ExpandWithLabel, which the generator first checks against every
ciphersuite-1 exporter in `tests/vectors/mdk/key-schedule.json` (labels used
as strings, as openmls's KAT runner does).  `exporter_step[0]`
(`00..1f` -> `73bd647f...6635`) is also the reviewer's independent value.
The case `from-exporter-epoch-9` is sealed under `exporter_step[1]`'s media
secret, so `test_media` decrypts it end to end from a stored exporter secret.

Negative cases carry MDK's verdict in `expect`, computed with MDK's receive
order (ciphertext hash, then AEAD, then plaintext hash):
`ciphertext_hash_mismatch`, `decrypt_failed`, `plaintext_hash_mismatch` or
`reject:<MediaAttachmentRejectionKind>`.

The `avatar_url.normalize` cases record what MDK's `url` crate (2.5.8)
produces; `avatar_url.stored` records MDK's decoder verdict on stored bytes.
libmarmot produces only a strict subset of the WHATWG serializer and decodes
three ways (valid / invalid / unverified, review M3).  `test_media` checks
the consensus properties on these: libmarmot never produces bytes MDK would
not, never refuses an MDK-canonical value, and calls a value invalid (or
valid) only when MDK does too.  The reviewer's 60,000-input differential
corpus gives the same result (0 forks, 0 refusals, 0 disagreements; 6,442
values MDK cannot parse are accepted as unverified, the documented residual).

## Regenerating `policy-verdicts-mdk-v0.11.0.json`

`policy-verdicts/` is a throwaway crate (`w24i-verdicts`) that calls MDK
v0.11.0's cgka-traits directly: `AgentTextStreamQuicPolicyV1::decode_component_state`,
`decode_encrypted_media_policy_v2` and `validate_and_normalize_blob_endpoint_url_v2`
(the `url` crate, 2.5.8). Not built by CMake or meson.

```sh
git clone --depth 1 --branch v0.11.0 https://github.com/marmot-protocol/mdk.git /tmp/mdk-v0.11.0
mkdir -p /tmp/mdk-v0.11.0/crates/w24i-verdicts
cp -r policy-verdicts/Cargo.toml policy-verdicts/src /tmp/mdk-v0.11.0/crates/w24i-verdicts/
# add "crates/w24i-verdicts" to [workspace] members in /tmp/mdk-v0.11.0/Cargo.toml
cd /tmp/mdk-v0.11.0 && cargo build -p w24i-verdicts && git diff --stat Cargo.lock  # only w24i-verdicts
python3 /path/to/policy-verdicts/gen_policy_verdicts.py /tmp/mdk-v0.11.0/target/debug/w24i-verdicts
```

The inputs are fixed (one seeded PRNG for the `0x8006` sweep), so the output
is deterministic. `test_media` requires libmarmot's `0x8006` verdict to be
MDK's on every case; for `0x800b` it checks the three-way consensus
properties above (never refuse an MDK-valid state, call a state verified
only when MDK accepts it, re-encode every verified state byte for byte, and
produce from a raw endpoint URL MDK's normalization or nothing).
