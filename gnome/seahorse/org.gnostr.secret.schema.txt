Schema: org.gnostr.Signer/identity   (gnostr_secret_schema, gnostr-secret)
Owner:  the signer daemon (org.nostr.Signer, nips/nip55l) is the only writer
        of private key material. Other components obtain signatures over
        D-Bus instead of reading this item.

Attributes:
- key_id=<selector the daemon looks the item up by; defaults to npub>
- npub=<npub1...>
- label=<friendly identity label, optional>
- hardware=true|false            (true iff origin=hardware)
- owner_uid=<unix uid, optional>
- owner_username=<unix username, optional>
- curve=secp256k1
- origin=software|hardware
- hardware_slot=<token-specific locator, optional>
- fingerprint=<first 8 hex chars of the pubkey, optional>
- created_at=<ISO-8601, optional>

Label format shown in Seahorse (gnostr_secret_store_build_label):
  "Nostr key: <label> (npub1xxxxxxxx…)"   when label is set
  "Nostr key: npub1xxxxxxxx…"             when label is empty
The npub is abbreviated to "npub1" + 8 chars in the label; the full npub is
always in the npub attribute.

Secrets:
- Software keys: the private key as 64 lowercase hex
- Hardware keys: do not store private material; store a small reference and
  set origin=hardware

Legacy schemas (migrated once per keyring by the signer daemon at startup;
originals deleted after a successful re-store; a marker item
org.gnostr.Signer/migration name=legacy-keys-v2 records completion. The
name is versioned: v1 predates org.gnostr.NostrKey, so a keyring carrying
only the v1 marker is scanned again):
- org.gnostr.Signer/key  {application,label,npub,key_type,created_at}
    label->label (and key_id, as StoreKey does for a non-npub selector),
    key_type->origin, created_at->created_at
- org.gnostr.Key         {type,npub,uid,curve,origin,hardware_slot}
    uid->label (and key_id), origin/hardware_slot kept; origin=hardware
    items are left in place (no private key to migrate)
- org.gnostr.NostrKey    {npub,application}   (gnostr client keystore,
                                              retired by nostrc-e5nz)
    only items with application=org.gnostr.Client (or none) are taken;
    secret nsec1 -> 64-hex; label="gnostr import", key_id=npub (the fixed
    label is not a selector); if the signer already holds a software key
    for the npub, the client copy is deleted without re-storing, so the
    existing item keeps its label
The marker item is labelled "Nostr signer migration marker (not a key)".

Schema: org.gnostr.WalletConnection   (gnostr_secret_wallet_schema, gnostr-secret)
Owner:  nostr-wallet-agent (org.nostr.Wallet1, gnome/nostr-wallet-agent). A
        separate secret class: the NIP-47 pairing, not a Nostr identity key.
        Exactly one item exists; pairing a new wallet replaces it.

Attributes:
- wallet_pubkey=<hex pubkey of the wallet service>
- client_pubkey=<hex pubkey derived from the pairing secret>
- relay=<first relay URL of the pairing>
- lud16=<lightning address, optional>
- created_at=<ISO-8601, optional>

Label format shown in Seahorse (gnostr_secret_wallet_build_label):
  "Nostr Wallet Connect: <lud16> (<8 hex>…)"   when lud16 is set
  "Nostr Wallet Connect: <8 hex>…"             otherwise

Secret:
- The full nostr+walletconnect://<wallet-pubkey>?relay=…&secret=…[&lud16=…]
  URI. Its secret= parameter is the per-pairing NWC client key; it is never
  the user's Nostr identity and is never exposed over D-Bus.
